| AAC capability and encoding | Export probes WebCodecs AAC-LC with 48 kHz/two channels before encoding; if unsupported, it drops the mix and marks the export as video-only (`js/exporter.js:1286-1313`). Encoding occurs before the muxer is instantiated (`js/exporter.js:1352-1378`), so encode failure should not leave a declared-but-empty soundtrack. | A saved report with an AAC-unavailable/encode-failed flag is distinct from a valid AAC track that Photos will not play. |

## Ranked explanations for a newly reproduced silent Photos file

These are *diagnostic branches*, not asserted defects. The ranking is conditional on obtaining a new file; the currently recorded report has not established that Photos is still silent.

1. **The sound is absent or silent in the exact delivered file** — highest priority to rule out, because it can be decided from the current file, but it is not supported by the 10 September report. The mix peak and loss flags should be from the same export; decode AAC and measure peak/RMS. Severity high; confidence **UNVERIFIED** for any new occurrence.
2. **The file played from Photos is not the same bytes as the completed export** (wrong share-sheet destination/selection, a canceled share, or fallback download followed by a different import). The code intentionally has both share and download branches; only compare the exact saved file's size/hash or copy that exact file back for inspection. Severity medium; confidence **UNVERIFIED**.
3. **A Photos-specific acceptance/interpretation difference for this exact MP4** despite a non-silent AAC track. Public Apple format documentation supports MP4/AAC broadly, but it does not certify every browser-produced MP4 and every Photos import path. Only compare the same file in Photos and Files/QuickTime on the same iPhone. Severity medium; confidence **UNVERIFIED**.
4. **A file-specific AAC timing or sample-table defect** (empty samples, invalid chunk offsets, time-to-sample duration mismatch, malformed AAC decoder configuration). This is lower after #604's measured healthy file, but a different export can still be inspected; do not extrapolate the older fixture. Severity high if confirmed; confidence **UNVERIFIED**.
5. **Audio is audible but very quiet or routed unexpectedly** (device mute/output selection/low source level). First compare the exact clip's original audio in Photos and the export; measure decoded RMS rather than relying only on an audio-track indicator. Severity low; confidence **UNVERIFIED**.

No ranked entry above is presented as a confirmed root cause. The prior four silent-output routes and the historical muxer suspicion were already dealt with in the requested backlog entries and are not reopened absent a new device report.

## Builder's MP4 inspection checklist

Inspect the exact `.mp4` that was saved from the share sheet, not merely the in-memory source or an older test export. Record the parser/tool version and file byte length.

1. Walk top-level `ftyp`, `mdat`, and `moov`; this muxer is configured with `fastStart:false`, so `moov` may be after `mdat`. A complete local file should still have a parseable `moov`.
2. Under `moov/trak`, identify the audio track by `mdia/hdlr` handler `soun`; verify an audio `trak` exists. Read `tkhd` and `mvhd` durations and compare to the intended clip duration (allow AAC frame rounding and any deliberate trim).
3. Read `mdia/mdhd`: for this exporter the audio timescale should be **48000** because the muxer audio track uses `sampleRate` as its timescale. The media duration should agree with the sample timeline.
4. Read `mdia/minf/stbl/stsd/mp4a`: expected audio sample entry is AAC (`mp4a`), two channels, 48,000 Hz. In `esds`, verify an AAC-LC AudioSpecificConfig (object type 2) and a coherent decoder configuration. These are the settings passed to the muxer at `js/exporter.js:1372-1378` and `vendor/mp4-muxer.js:1639-1652`.
5. Read `stsz.sample_count`: it must be greater than zero for an audio track with encoded samples. Read `stts` entries and calculate `sum(sample_count × sample_delta) / mdhd.timescale`; it should represent the encoded audio duration, close to project duration within AAC frame/priming handling. Do not require one exact sample count without the project duration and encoder behavior.
6. Resolve `stsc` plus `stco`/`co64` chunk offsets and sample sizes: every referenced byte range must land inside `mdat`. Check for an `edts/elst` edit list if present and validate its media-time/rate mapping; this exporter intends to trim AAC priming itself, so an edit list is not expected to be required.
7. Decode the AAC samples from that same file and report channel count, decoded duration, peak and RMS. A valid `mp4a` box with nonzero samples can still decode to silence; box presence alone is not proof of sound. Compare with the mixer's reported peak.

Interpretation: **no `soun` track** points to the pre-mux/mix/codec branch; **`soun` with zero samples or invalid offsets** points to mux/sample tables; **nonzero samples decoding to near-zero RMS** points to silent input/mix; **non-silent AAC that plays in Files but not Photos** isolates the problem to the Photos/import route much more strongly than to audio mixing.
