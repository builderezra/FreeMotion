## #1062 Pixel Motion smear is built at 480 px in preview and 720 px in export (LOW)
- **Claim: Verified (Measured again, not just Read).** `js/compositor.js:13354` `Math.min(FM._exporting ? 720 : 480, W)`. 1080x1080 text, Drift 600 px/s, Pixel Motion at Amount 0.5: preview vs export frame differ by up to **46 levels, 6,695 px over 8, 28 over 32** (Amount 1: max 33, 4,347 px over 8). The probe is `p19_1062_probe.py`.
- **Callers traced (Read).** `WW` is local to `CANVAS_FX.motionflow` style 0; the only entry is `drawContentMotionBlur` (`:16438`, called from `drawLayer` at `:17290` when the outer effect is `motionflow`), so one render path serves the editor, the paused frame and the exporter. `FM._exporting` is the only thing that switches the width.
- **Cost measured before choosing.** With a single 720 for everything the diff is **0** but the preview frames that contain flow cost about 35% more here (about 55 to 88 ms became 80 to 117 ms in software headless Chromium; noisy, a device number is still a **Guess**). #202 (lag) is open, so I did not make playback pay it.
- **Patch.** `(FM._exporting || !FM.playing) ? 720 : 480`: 720 whenever nobody watches it move (paused, scrubbing, export), 480 only during live playback. A paused frame is then the export frame. `FM.playing` is app.js:8's flag, the same one `app.js:231` uses.
- **Not fixed, said plainly.** While PLAYING the cutoff (0.8 working px) and the ramp still sit at different real speeds than export. ChatGPT's "at minimum" fix (express them in flow units, `len * F.FW / WW`) would remove that and is independent of this patch; I left it because it changes how every existing Pixel Motion looks in export too (it is the same maths with a different width), which wants his look-check first.
- **Test.** `P19 #1062`: Smear (style 1) preview vs export <= 2 as CONTROL; Pixel Motion paused preview vs export <= 2; Pixel Motion while PLAYING must still differ from export (so export lowered to 480, or playback raised to 720, both go red); the probe frame must not be empty. **Mutations:** back to the old width (A1), export at 480 (A2), always 720 (A3): all CAUGHT.
- **Risk.** Low. Pinned-picture tests are unaffected (they render paused and not through this path at a changed size: Guess, the neighbouring slice below is Measured).

## #1063 Rotate handle jumps by 360 across the left of the pivot (LOW)
- **Claim: Verified (Measured).** `js/canvas-edit.js:682`. Pressing at 170° and dragging 2° at a time: rotation goes 0, 2, 4, 6, 8 then **-350**, -348 ... -340 (should be +20). The layer looks right but the Move & Transform box jumps, and a new key written against it spins the long way.
- **Callers traced (Read).** The drag starts only at `rotH` (`:1027`, `startHandle('rotate')`, state at `:539`) and moves in `onMove` (`:681`); nothing else reads `drag.startAngle`. The two other rotate gestures already do it right: the pinch path (`:572`, wraps each step) and the inspector dial (`inspector.js:5175`, accumulates `rd.acc` with `d -= 360 * Math.round(d / 360)`). So this is the one outlier, and the fix is the same idiom.
- **Patch.** Keep `lastAngle` and `turned` on the drag; each move adds the step wrapped into (-180, 180]; `deg = startRot + turned`. The pivot maths after it uses `deg - startRot`, so it needs no change.
- **Test.** `P19 #1063`: real `pointerdown` on `.sb-rot` and window `pointermove`s: control 10° to 30° gives +20; 170° to 190° gives +20 with no step over 4; back 190° to 170° gives -20; a whole lap -90° to 270° ends at +360. **Mutations:** no wrap (B1), absolute angle again (B2): both CAUGHT.
- **Risk.** Very low. One behaviour change a person could feel: past 180° the box now keeps counting (190 rather than -170); that is what the dial already does.

## #1064 The cache-buster gate misses every `?v=` file that is not js/*.js or the two stylesheets (LOW, tooling)
- **Claim: Verified (Read plus Measured).** `tools/ship.sh` had the regex `^(js/.*\.js|styles\.css|theme-glass\.css)$` **three times** (find, bump, re-check). Not covered, and each is cached forever by `sw.js` (#112): `vendor/mp4-muxer.js?v=9`, `manifest.json?v=2`, `apple-touch-icon.png?v=2`, `icon-192.png?v=2`, `splash-v2.mp4?v=1`, `brand-wordmark-m.png?v=1` (index.html:674 AND six lines of styles.css), and `fx-art/<key>.jpg?v=1` (built in `js/fx-thumbs.js:56`, so no file name appears anywhere). `p19_1064_old_gate.py` shows the old gate watching only `js/app.js` of six changed files.
- **Fix.** `tools/_busters.py` drives the gate from the REFERENCES: a changed file is a miss when index.html, a stylesheet or a js file carries `<path>?v=N` for it and N is the same as at HEAD (a reference new since HEAD is exempt, a file nothing references is not cached); `fx-art/` is a named templated prefix. ship.sh calls `--miss`, `--bump`, `--miss`, and runs `--selftest` before it, next to the classifier's.
- **A bug the real tree showed me that a unit test would not have.** Bumping the wordmark edits `styles.css`, which makes styles.css itself a changed file with a stale `?v=` in index.html; same for `js/fx-thumbs.js`. A single pass left them stale and the re-check would have refused the whole ship. `settle()` bumps to a fixpoint (at most 6 rounds); I proved it on the real files (touched the four assets, bump, clean) and put the cascade in the self-test (**14 checks**).
- **Mutations (eight, all CAUGHT):** empty-equals-empty, no stylesheet source, no templated prefix, bump only the first occurrence, equal-ignored, templated-never-equal, settle once, cascade not tracked. A seventh original one (dedupe) survived because that code was dead; I deleted the code rather than the check.
- **Open edge.** Non-integer busters are refused, not bumped (none exist today). `sw.js` is deliberately not a source: it names the wordmark only in a comment.
- **Cost.** About a second per ship (a temp git repo, 14 checks). New files: `tools/_busters.py`. Add it to the port's self-test list in `tools/test-port.sh` when landing (**Guess**: I did not run the port on this machine).
