## #1099 Opening a file can freeze the app: caps and shape checks at the import door
- **Claim: Verified (the helper's measurements, not re-measured by me).** `hunt/import-robustness` timed hostile files against v17.23 (100 layers x 20 glows over 60 s; 40,000 keyframes 9 s; 80,000 path points 10 s; 200 fonts accepted with no cap; `project: "x"` throws after `projects.create` has already run). I did **not** repeat the freeze timings; I tested that the new door refuses each shape cheaply.
- **Design, as the PM verified it (Read, in the entry):** every cap lives at the import door, never in `sanitizeKeyframes` or `sanitizeImportedLayers`, because `history.restore` runs those on every undo and redo, so a cap there would cut a saved project on the first undo and the autosave would keep the cut. `FX_MAX` stays 120. Layers keep their unknown fields.
- **Patch (`p24-1099.patch`, `js/storage.js`, buster 58 to 59).** `FM.storage.sceneFileProblem`, which runs before `projects.create` in `importObject` (and so for `restoreBackup`, which calls `importObject` per project), now also refuses: a `project` that is not a plain object; more than 16 embedded fonts, or fonts that are not an object; any layer property with more than 2,000 keyframes; any drawing (`subs` or `points`) over about 20,000 points (60,000 nodes). Each refusal is a plain sentence and costs a bounded walk (the test requires under 150 ms even for 100,000 points or 40,000 keyframes). `importObject` then drops non-object entries from the layer list (a stray number or null) and opens the rest.
- **Test.** `P24 #1099`: controls first (an empty project, 2,000 keyframes, 5,000 points and 16 fonts all pass the door check), then the seven refusals by their message, then through `importObject` that `project: "x"` and 40,000 keyframes create no project and say something, and that `[1, "x", null, [], layer]` opens with exactly one layer. **Mutations CAUGHT (5 of 5):** project check off, keyframe cap off, path cap off, font cap off, stray-entry filter off.
- **Not covered, said plainly.** (1) The "100 layers x 20 effects freezes for over 60 s" case (the entry's H1) is **not fixed**: the product of layers and effects is not what any cap here bounds, and the helper's own fix (open with effects paused plus a banner) needs a design first, per his rule that nothing visible ships unseen. (2) The caps run at `sceneFileProblem`; **I did not check the other two doors the PM names**: the template and element insert, and the collab host's accept path. They should call the same check; Read only. (3) The 16-font limit and the 2,000-keyframe limit are the helper's suggested numbers, not measured limits of what a real project needs; a project with 17 fonts would now be refused (Guess: rare). (4) Text length (M2) and the font `css` string (the separate #1102) are not touched. (5) `FM.fonts.applyEmbedded` itself still has no cap for callers other than the file import (the collab path has its own size cap).
- **Open choice for Ezra or the PM:** refuse or trim. The entry says refuse; for keyframes and points a refusal means a long hand-animated project from a newer build cannot be opened at all. Trimming silently would lose his work. I followed the entry.
