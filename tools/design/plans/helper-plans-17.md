## #1051 A project that is a plain value ("project":"x") passes the import gate and throws (LOW)
**Where (Read):** `sceneFileProblem` (js/storage.js:1974) and `applyScene` (:1694) test `!obj.project` only; `clampProjectDims` (:1004) assigns `p.width` and friends, which throws on a string, number or boolean in strict mode. `reIdLayers` (:2049) walks `l.id` / `l.start` on every layer entry.
**Callers traced:** `applyScene` has ONE caller, `importObject` (:2000), which is reached from `importFile` (:2026, a user's file) and `restoreBackup` (:1951, once per project). `clampProjectDims` has eight callers (:890 load, :1697 applyScene, :1777, :2558 `projects.create`, :2704, :3207, :3480, and the collab host's project invariant, `js/collab-bridge.js:147`, which runs it on whatever a peer's write holds), so the guard goes in the function itself as well as in the gate.
**What happens (Measured, `results/probe-1051-main.json`):** on main, `project` = `"x"`, `5` or `true` each THROW out of `importObject` ("Cannot create property 'width' on string 'x'") and leave **one empty project behind**; the toast that follows is the generic *Could not read that project file* from `importFile`'s catch. **`project: []` is not refused at all:** it "imports" (*Project imported*) as a project whose `project` is a list. A layer entry that is `null`, `"x"`, `5` or `[]` each throws (`reIdLayers`), also leaving a junk project.
**Plan (patch, 43 lines):** `isPlainObj` (not null, not a list, not a primitive). `sceneFileProblem` refuses a non-object `project` with the **existing** *missing its canvas settings* sentence and a non-object layer entry with a new one: *"That project file has a layer that cannot be read — it may be damaged."* (the wording is a call for Ezra). `applyScene` repeats both checks (it has its own guard, per its own comment). `clampProjectDims` returns early on a non-object.
**Test:** eight bad files (four `project`s, four `layers`) each return false, throw nothing, leave the project count unchanged, say something that is not the generic catch; `applyScene` called directly answers false for three of them; `_clampProjectDims` called on seven non-objects never throws and writes nothing onto a list; CONTROL: a well-formed file imports (+1 project). Red on main (threw), green patched. Mutations (Measured): the clamp guard removed → red (the direct call throws); the project check back to `!obj.project` → red; the layer check off → red; the `applyScene` guard back to `!obj.project` → red (it threw `Cannot create property 'duration' on string`).

## #1055 Pixelate's Block aspect and Edges do nothing on an adjustment layer (LOW)
**Where (Read):** `applyAdjustmentFilters` (js/compositor.js:17988) reads only `size` (:18140-18157) and passes only `size` to `pixelateOnFrameGrid` (:17906); `drawPixelate` (the clip path) reads `aspect` (25-400) and `smooth` (0 / 1) and honours both.
**Callers traced:** `pixelateOnFrameGrid` has one caller (that line); `applyAdjustmentFilters` is reached from the adjustment layer's draw and from the adjustment filter container (:18070). The export uses the same compositor code, so preview and export agree on the fix (Read: `js/exporter.js` has no pixelate of its own).
**What happens (Measured):** an adjustment layer with Pixelate at Block aspect 25, 100 and 400 renders identically (0 / 0 / 0 bytes differ); Edges = Soft renders like Blocks. The clip path honours both (the test's control).
**Plan (patch, 69 lines):** read `size`, `aspect` and `smooth` once, as `drawPixelate` does (`sizeY = size × aspect / 100`, soft = `smooth` rounds to 1); the whole-frame branch uses `sizeY` for the block count and `imageSmoothingEnabled = soft` for the upscale; `pixelateOnFrameGrid` takes `sizeY` and `soft` (block height from `sizeY`, smoothing from `soft`). Defaults (aspect 100, smooth 0) give today's exact numbers.
**Test:** the whole-frame branch (aspect 25 / 100 / 400 and Soft each differ from Blocks) and **the export-grid branch** (a cropped canvas stamped `__fmCrop`, `__fmOX/OY` ≠ 0, which is what a zoomed preview is), each with a control that Pixelate shows at all. Red on main, green patched. Mutations (Measured): aspect ignored (whole-frame) → red; Soft ignored (whole-frame) → red; aspect ignored in the grid → red; Soft ignored in the grid → red. **Not covered:** that the clip path is byte-identical before and after (I did not freeze a hash, which would not survive another Chromium); it is held by the patch not touching `drawPixelate`, and by the neighbouring tests below.
