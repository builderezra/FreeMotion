## #1015 Offline edits go out as an overwrite if the guest edits again before the host's catch-up reply

**Reproduced.** Guest offline, renames layer A (cid 1); owner renames it (newer); guest `setOnline(true)` (the hello is out, the reply is not delivered yet), edits again (cid 2). Every tx on the wire: **`[cid1 q:0, cid2 q:0]`**, and after the loop settles **the owner's layer ends named with the guest's stale value** ("guest again before the reply", expected "owner newer"), no clash, no toast. (The existing test at `tests/tests.js:31980` only checks the pre-outage tx, and it does check q:1 for that one, which is why it stays green.)
**Where (Read).** The host runs its compare-and-set only for `tx.q === 1` (`js/collab-host.js:873`). The guest decides `q` in `flushOutstanding` (`js/collab-session.js:346-353`): `q = (e.queued || e.replay) ? 1 : 0`. `queued` is set only in `markOffline` for entries that **already exist** (`:1369-1371`) and in `recoverOutbox` (`:1363`). So two kinds of entry are `q:0`: (a) one **created while offline** (`pushLocal` builds `{ cid, ops, sent: false }` at `:287`, no flag; `runStep` at `:1219` the same) and (b) one created after `setOnline(true)` and before the reply. `replay` is only stamped by `replayOutstanding` (`:1028`), which runs on a `tail` (`:830`) or a `snap` (`:1022`), i.e. after the reply. Any `pushLocal` in the gap calls `flushOutstanding` (`:318`, `if (S.online)`) and ships everything unsent, `q:0`.
**Callers traced.** Entry creation: `pushLocal` (`:287`), `runStep` guest branch (`:1219`), `recoverOutbox` (`:1363`, already `queued:true`). Reconnect: `S.setOnline(true)` is called from `js/collab-session.js:592` (the link re-opening while quiet) and `js/collab-ui.js:4539` (the manual retry). The only sender of a `tx` is `flushOutstanding` (`:352`). Host side: `:861` drops a duplicate cid, `:873` is the CAS. The `before` values that CAS needs ride only on `q:1` (`stripBefore` at `:350` removes them for q:0), so a q:0 tx cannot be checked even if the host wanted to.
**Build (one place for the decision, as the entry says).**
1. A flag `catching` on the session: true from `setOnline(true)` (set right before the hello is sent, `:1387`), false in `replayOutstanding` (every path that ends the catch-up passes it) and at `welcome` is NOT enough (a welcome does not carry the tail).
2. One `enqueue(entry)` (see #1019, same helper) stamps `queued: !S.online || catching` on every new entry.
3. In `setOnline(true)` also stamp `queued = true` on everything outstanding (offline-made entries from before this change's flag).
4. If the host never replies, `catching` stays true and every tx is `q:1`: harmless (a CAS on an unchanged value passes), but costs the `before` bytes on the wire (Guess: small).
**Test.** Extend the test above, or a sibling `1015 …`: the repro as written plus `final === 'owner newer'` and `g.G.lastClash` set; an Undo variant (`g.G.undo()` in the gap instead of the second edit, using `afterCommit()` as the suite does at `:40660`). **Mutations:** drop the offline stamp (the cid1 half goes red); drop the `catching` stamp (the cid2 half goes red). Each should be caught by a different assertion, so run both.
**Effort:** an hour with the test. **Risk:** low; q:1 is the safe direction. **Check in ChatGPT's commit:** it must cover entries made **while offline**, not only the gap after reconnect (a fix that only sets `queued` in `setOnline` misses entries created later in the same outage if `markOffline` is not re-run), and the Undo path.

## #1016 Volume, Position, Scale, Size and Skew values cannot be reached from a keyboard

**Reproduced** (Volume panel): the box has `tabIndex -1`, no role, no aria-label; `val.focus()` does not take focus; an Enter keydown does not open the editor; **both** `.fx-scrub-val` inputs in the panel have no accessible name (2 of 2).
**Where (Read) and a correction.** The box is `mtVBox` (`js/inspector.js:4384`), `val = el('div','mt-vbox-val')` at `:4387`. **It has 19 call sites, not the six the entry lists**: Width/Height `:4716-4717`, point X/Y `:4846-4847`, **Position X/Y/Z `:5009-5011`, Rotation `:5161`, X/Y tilt `:5165-5166`, Scale Width/Height `:5225-5226`, Anchor X/Y `:5335-5336`, Skew `:5359-5360`, Volume `:5616`**. One fix in `mtVBox` covers all of them. Typing opens only from a pointer tap (`startEdit`, `:4542`, called from the `pointerup` branch just above it). The commit on Enter is `setVal(clamp(n), true); commitH()` (`:4543`). The key handling that exists (`onKey`, `:4545`) is only installed while editing.
**Callers traced.** `mtVBox` returns `box` with `box._refresh`; `refresh` (`:4441`) rewrites the text only when not editing. The label `lab` of the keyframe-selectable boxes is already a keyboard button (`tabIndex = 0`, `role=button`, `:4408-4410`), so the label is reachable and the number is not. `js/mobile.js:118` lists `.mt-vbox-val` in a selector of things a phone grab must ignore: no change. The `.fx-scrub-val` inputs are built at `js/inspector.js:223, 1164, 1351, 1383` (and `typeInBox(val, min)` is the shared helper).
**Build.**
1. In `mtVBox`: `val.tabIndex = 0; role=spinbutton; aria-label=labelText`; in `refresh` also set `aria-valuenow` (and `aria-valuemin/max` when `opts.min/max` exist).
2. A `keydown` on `val` while not editing: Enter or Space → `startEdit()`; ArrowUp/ArrowRight → `+step`, ArrowDown/ArrowLeft → `-step` (Shift x10, Alt x0.1; base step 1, which is a pixel for a position and a degree for a rotation, **Guess**: one fixed step suits all 19, otherwise add `opts.keyStep`), each as `setVal(clamp(v), true); commitH(); refresh()` so **one key press is one undo step**, exactly as a typed value is. `e.preventDefault()` so the arrows do not scroll the card.
3. Give each `.fx-scrub-val` `aria-label = p.label` (or the passed label) at its four creation sites. Making `.fx-scrub` a `role=slider` is the entry's optional part; leave it out of the first commit.
4. **A visible focus ring is a visual change (#545):** style only `:focus-visible` (keyboard users only; a tap never shows it) and show him one screenshot before it ships.
**Test.** The repro as written (focusable, role, name, Enter opens the editor) plus: Tab-order reaches the box after the label; ArrowUp on Volume 100 gives 101 and **one** `FM.history` step (undo returns it); Escape leaves the value unchanged; every `.fx-scrub-val` on the Effects sheet has a non-empty name. **Mutation:** remove the keydown handler (Enter test red); remove the aria-label line (name test red).
**Effort:** two hours (the effect-scrubber labels are the fiddly half). **Risk:** low; the one real risk is the arrows firing while a pointer scrub is in progress, so ignore keydown while `drag` is set.

## #1017 Tab always cycles layers, even with a button focused

**Reproduced.** Select layer A of two, focus `#btn-export`, dispatch a Tab keydown: **`defaultPrevented true` and the selection moved to layer B.**
**Where (Read).** The branch is `else if (e.code === 'Tab') { e.preventDefault(); … select next/previous … }` at `js/app.js:8956`, in the long else-if chain of the global `keydown` handler that starts at `:8794`. Gates above it that already return: `inEdit` (an input, select, textarea or contentEditable, `:8796`, with `if (inEdit) return;` at `:8899`), an overlay owning the screen (`:8820`), an open effects browser (`:8826`), the text editor (`:8841`), and the **drawing tool** (`:8851`), which **deliberately** `preventDefault`s Tab ("Tab would walk focus off the drawing"). Layer heads are plain `div.track-head` (`js/timeline.js:1345`), not focusable.
**Callers traced and what pins today's behaviour.** The suite pins the DRAWING half: `tests/tests.js:98881` presses a real Tab (trusted key through `tests/_cdp.py`, `KEY690c.tab`) and expects it not to walk focus while drawing, so **the fix must not touch the drawing branch**. Nothing pins "Tab cycles layers with focus on the body" (no test presses Tab and reads the selection), so add the control. `FM.overlayOwnsScreen` and the browser branch return before the chain and are unaffected.
**Build.**
1. At the Tab branch: `const ae = document.activeElement; if (ae && ae !== document.body && ae !== document.documentElement) return;` (no `preventDefault`, no cycling), i.e. cycle layers only when nothing in particular has focus. Shift+Tab the same. **Trade-off to tell him:** after clicking a button (Chrome focuses it), Tab walks the controls and no longer changes the layer; clicking the canvas or a layer row (focus returns to the body) brings the layer cycling back. Safari does not focus a button on click, so there it changes nothing. **Guess:** no one on PC relies on Tab-cycles-after-clicking-a-button; the ? sheet (`js/shortcuts.js`) does not list Tab at all, so no text goes stale.
2. The accessibility half (roving tabindex plus `role` and `aria-selected` on `.track-head`, `aria-label` on the eye and lock spans at `js/timeline.js:1349/:1369`) is a larger, separate change. If heads become focusable, `activeElement` after clicking a head is the head, so step 1's gate must also pass `ae.classList.contains('track-head')`, or clicking a layer would switch Tab cycling off. Do 1 first; do 2 only with a `:focus-visible` look he has seen.
**Test.** The repro as written; the control (focus on body: Tab cycles and is prevented); Shift+Tab both ways; **and a real Tab** with the harness's trusted keys (`realInput924([KEY690c.tab], …)` as at `:98881`) with `#btn-export` focused, asserting focus moved on and the selection did not. The drawing test at `:98881` must stay green. **Mutation:** delete the gate (repro red).
**Effort:** 30 minutes for step 1. **Risk:** low for step 1. **Check in ChatGPT's commit:** that it kept the drawing-tool branch, and that "focus on a layer head" does not turn the cycling off.

## #1018 The persistent-storage answer is thrown away

**Measured.** After load, `'storagePersisted' in FM` is false: nothing records the answer.
**Where (Read).** `js/storage.js:326-333`, the only call site: `navigator.storage.persisted().then(p => { if (!p) return navigator.storage.persist(); }).catch(() => {})`. The quota toast is `warnStore` (`:313-324`), called from the media write failures; the only other `storage.estimate()` readers are `js/collab-media.js:749` and `js/collab-ui.js:3255` (both about room for a transfer, not about protection).
**Callers traced.** `warnStore` is called with `(e, key)` from the media writers in this file (it ignores cache keys: `thumb:`, `libthumb2:`, `xr:`, `:309`) and warns once per key (`_storeWarned`). Nothing else reads the persistence answer, so storing it is additive.
**Build.**
1. Wrap the block in a named function `askPersistentStorage()` (exposed as `FM.storage._askPersist` for the test) that sets `FM.storagePersisted` to `true` (persisted already, or `persist()` resolved true), `false` (persist() resolved false, or persisted() false and persist unsupported) or leaves it `null` (API missing or threw). Never throws.
2. In `warnStore`, when `quota` and `FM.storagePersisted === false`, append one sentence: "Your browser may clear saved media when space runs low." Say nothing when it is `true` or `null` (a message that claims protection we do not know about is worse than silence).
3. A line in the Labs report if one exists for storage (the only report I found is the collab connection report, `fm.lastConnReport`, which is not storage); if there is none, **do not invent one**, leave the value on `FM` and in the quota toast only (the entry says "otherwise stay silent").
**Test.** Stub `navigator.storage.persisted`/`persist` to resolve `false` and call `FM.storage._askPersist()`; assert `FM.storagePersisted === false`; stub `persisted` true: assert true and `persist` not called (spy); stub both missing: `null` and no throw. Then force a quota error through `warnStore` (the suite has a refused-write seam, `FM.storage.collabPut` stub style at `:32010`) and assert the toast text includes the sentence only when false. **Mutation:** keep the answer but drop the toast condition (the true/null cases go red).
**Effort:** 45 minutes. **Risk:** none. **Guess:** on iPhone Safari `persist()` mostly resolves false for a site that is not installed to the Home Screen; if so the sentence will show to nearly every non-installed iPhone user on a full-storage error, which is true but should be worded as advice ("installing the app helps") only after checking that on a device.

## #1019 Offline Undo and Redo skip the outbox cap, and acks then undercount

**Reproduced.** 1,200-layer guest, offline: one rename of all layers (1,200 ops), then nine alternating Undo and Redo steps (each closed with `afterCommit()`). Outstanding ops **1,200 after the edit and 12,000 after the nine steps**, against `LIM.OUTBOX_OPS = 5000` (`js/collab-core.js:77`), and `outboxFull` stays **undefined** (VERIFIED.md reproduced 25,200 in JSC). **By arithmetic, not run:** when the acks land, `onAck` (`js/collab-session.js:913-914`) subtracts every entry's size, including the ten that were never added, so `outboxOps` goes to 1,200 - 12,000 = **-10,800**, and from then on the cap would not trip until an outbox of about 15,800 ops (Computed in my head: 5000 + 10800; the code was not run for this part).
**Where (Read).** Accounting is only in `pushLocal` (`:296-304`: `outboxOps += ops.length`, `outboxBytes += canon(ops).length`, then the cap check that sets `S.outboxFull`, keeps my version and calls `onOutboxFull(true)`). The guest branch of `runStep` (`:1215-1219`) pushes `{ cid, ops, sent:false }` with none of it, and `recoverOutbox` (`:1363`) likewise. `runStep` begins with `pushLocal('hot')`, which does honour `outboxFull`, but then the undo's own ops bypass it. While `outboxFull`, a normal edit is reverted to base (`:243`); an Undo is not refused.
**Callers traced.** `runStep` is reached only from `S.undo` (`:1233`) and `S.redo` (`:1240`); those are reached only from `C.undo`/`C.redo` (`js/collab-core.js:350-351`), which `FM.history.undo/redo` call while collab owns undo (`js/history.js:325-326`), from the toolbar buttons (`js/app.js:7162-7163`) and the keyboard (`js/app.js:8856`, `:8859`). Entries leave `outstanding` only in `onAck` (`:910-918`), so the accounting has exactly two writers (push, ack) and the fix is to make the push side one function.
**Build.**
1. `enqueue(entry)`: `outstanding.push(entry); outboxOps += n; outboxBytes += canon(entry.ops).length;` then the cap check currently inline at `:300-305`. Use it in `pushLocal`, `runStep` and `recoverOutbox`. (Shares the `queued` stamp with #1015: do both in one commit.)
2. In `runStep` for a guest, **before applying** the step: if `S.outboxFull`, put the step back on its stack and return `false` (the same shape as the role refusal at `:1198-1204`, so the button state stays right), rather than apply and queue. A reverted edit says nothing today because the read-only banner is already up (`onOutboxFull`).
3. Clamp the subtraction in `onAck` at 0 as a belt (`Math.max(0, …)`): it hides nothing, because step 1 makes it exact, and it turns a future miscount from "cap disabled" into "cap slightly early".
**Test.** The repro as written, asserting `outboxFull` true and `onOutboxFull(true)` fired by about the fifth step; then settle the acks and assert an edit just over the cap trips it again (the undercount half: today it would not). A refused undo (`outboxFull` true) leaves the step on the undo stack and `canUndo()` true. **Mutations:** `runStep` uses plain `push` again (repro red); `onAck` without the matching `enqueue` accounting (the second half red).
**Effort:** an hour with #1015 in the same commit. **Risk:** low; the one behaviour change is that Undo does nothing while the outbox is full, which is how an edit already behaves. **ChatGPT's "medium" is too high** (VERIFIED.md agrees: the cost is a slow resend, not data loss); **check in its commit** that `recoverOutbox` is covered too, since the entry names only `runStep`.
