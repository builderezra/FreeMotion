# #1243, area F: research and feasibility (S16, S17, S20, S29, S33, AI1)

Planned 8 Nov 2026 from a read-only pass over the tree at v18.29, plus web research where a clause needs it. Nothing was
run or measured. Every "from reading" claim is labelled as such.

**The labels used below, so the verdicts read the same everywhere:**
- **HAVE**: already in the app (file:line given). "Full only" means Simple has no door to it yet.
- **LOCAL**: buildable in plain JS/canvas/Web Audio, no model, works offline.
- **LOCAL ML**: buildable on the device with a model loaded once from a CDN (a `<script>` tag plus weights cached by the
  browser). Nothing the user makes leaves the device. Costs a one-time download and is slow on a phone.
- **BYOK**: needs a cloud AI with the user's own key, never a key in our code. Their media or text leaves the device for
  that one call. Today the key store only holds an Anthropic key (`js/ai-key.js:14`, `:19`), and Anthropic's API has no
  speech-to-text or text-to-speech, so every BYOK audio feature below also needs a second key type.
- **NOT FEASIBLE**: not at usable speed or quality on a phone, in a browser.

Model sizes are approximate from memory and model cards. Check each one at build time.

### #1243 S16: Stickers and GIPHY

**His words (verbatim):** "Also, I don't know if it's possible, but CapCut has like a stickers menu and then they have like all of the Giphy stickers. I don't know if we can add that or not, if like that's free or whatever, but if we could, that would be great."

**Verdict.** GIPHY can be built, but it can't ship under his rules today. A sticker shelf of our own works offline and is **LOCAL** (recommended).

**What's there now**
- There is no sticker library. Simple's design parks it as "Later": `tools/design/plans/simple-mode/DESIGN.md:2876` ("sticker and music libraries").
- Animated GIFs already play, preview and export. The plain-JS decoder works on iPhone Safari, with at most 1000 frames and half the frame-cache budget (`js/media.js:618-644`).
- Simple adds a picked file as an overlay in one undo step (`js/spine-edit.js:2484` `addOverlay(files)`). A sticker is clamped to the track end (`js/spine-edit.js:1515`).
- Saved elements are already tiles in Simple's Extras (`js/simple-tools.js:1045-1139`), added by `addElement` (`js/spine-edit.js:3692`).

**GIPHY, researched (web, Nov 2026)**
- Keys are free, but you need one per app *and* per platform. Beta keys get about 100 calls an hour and are not for production. A production key needs an application that includes screenshots of the attribution.
- "Powered By GIPHY" must be shown wherever the API is used.
- GIPHY's docs forbid caching responses or media URLs, or storing copies of media, unless GIPHY explicitly approves media caching and you follow their revalidation scheme. Proxying is not allowed.
- **This is the blocker.** A FreeMotion project has to keep a sticker in IndexedDB so it survives a reload, plays offline and exports. That counts as storing a copy, which needs GIPHY's approval.
- **Keys.** GIPHY's normal route is one app key in the client, which breaks his "never hardcode keys" rule. BYOK would mean every user opens a GIPHY developer account, and in practice nobody will.
- **Alternatives.** Tenor is gone: Google shut its API down on 30 June 2026. KLIPY is free, ad-supported, needs attribution and needs approval for production, so it raises the same storage question.

**The change (pick A)**
1. Add `js/stickers.js`: a registry of `{id, name, tags, kind: 'element'|'gif', src}`. It makes no network call at boot.
2. **Pack 1, our own:** 30 animated stickers drawn as FreeMotion elements from shapes, text, effects and keyframes: arrows, bursts, underlines, sparkles, hearts, frames, and chips with our own words. They are vector, can be recoloured, and need no licence. Store them as element JSON under `stickers/` and add them through `addElement` (`spine-edit.js:3692`). Show him 6 first (#545).
3. **Pack 2, emoji:** 60 to 80 of Google's Noto Animated Emoji (CC BY 4.0), served as GIFs from our own origin (`stickers/noto/*.gif?v=`) so `sw.js` caches them. On a tap: fetch, make a File, call `S.cmd.addOverlay([file])`, and the bytes land in IndexedDB like any import. Add a credit line in Settings › About.
4. **"Your GIFs" tile:** opens the file picker. GIF import already works.
5. **The sheet:** a grid with tag search. 4 columns at 380 px, 8 at 1280 px. It covers the same height as the Add menu (F3/F10), and opening it closes the bottom row (S9).
6. **GIPHY stays parked** until GIPHY approves caching for an offline editor. Then it becomes Settings › Labs › "GIPHY (your own key)", with the mark shown. That's his call.

**Tests**
- **At 380 px:** open the sheet and tap the first emoji. Expect exactly one new overlay at the playhead, exactly one history step, the sheet closed, and no horizontal page scroll. **At 1280 px:** the grid has at least 6 columns.
- **Offline:** add a GIF sticker, stub `fetch` to reject, then reload the project. The media record still has its bytes and draws a non-blank frame. **Mutation:** keep the remote URL instead of storing the blob → red.
- **Boot:** count fetches under `stickers/` at boot and expect 0. **Mutation:** preload the registry at boot → red.

**Pick (which packs).** A: our own pack plus Noto emoji, **RECOMMENDED**. B: A, plus GIPHY with the user's own key, opt-in. C: KLIPY. "Stickers" is a generic word (WhatsApp and iMessage use it), the same kind of plain craft name #954 kept, so no rename is needed.

**Size.** M for the code, L for the 30 drawn stickers. **Depends on:** S8 (sub-menus), S9 (one menu at a time), S15 (scrolling bottom row), F3 (height rule).

- **Lyrics:** stub the engine's words with timestamps. Expect cues to land at those times, in layer-local seconds. **Mutation:** write project time instead → red after moving the song.

**Pick.** Names that differ from CapCut's ("Text template", "Text to audio", "Auto lyrics"): "Title looks" / **"Read it out"** / **"Song words"** (RECOMMENDED). Alternatives: "Ready titles" / "Voice it" / "Lyrics from song".

**Size.** Draw S; titles M; voice L; lyrics L. Build order: Draw, then titles, then the speech engine (lyrics + S33 Transcript), then voice. **Depends on:** S8 (Text opens a sub-menu), S36 (the text editing rethink).

**The change**
1. **A third tab in Simple's Look panel** (`js/simple-tools.js:851-864`, which today has Filters and Adjust). It holds 7 toggle tiles, each with a Strength row. A tap adds or removes the effect on the selected clip as one Simple command, `S.cmd.quality(id, kind, on)`, with tuned defaults. These tools are per clip: they read that clip's frames. That conflicts with S12's project-wide Look, so this tab shows only when a clip is selected.
2. **Stabilize (L).**
   - At about 160 px wide, estimate each frame's shift and turn from the one before. Reuse the `:19040` block matcher and take the median of the vectors.
   - Smooth the path with a moving average whose window comes from the strength mode.
   - Write the inverse x, y and rotation as keyframes, plus the smallest scale that keeps the edges covered.
   - It runs chunked with yields, shows progress, and can be cancelled (the `captions-vad.js` pattern).
   - Modes: "Gentle / Steady / Locked" (CapCut's are "Recommended / Minimum cut / Most stable").
3. **Smooth motion (M).** Flow-warped in-between frames for speeds below 1×, reusing the frame cache that `frames.js` builds for frame blend.
4. **Sharpen for 4K (S).** Export at 2160p with an unsharp pass, named honestly.

**Tests**
- **At 380 px:** with a video clip selected, Look › Quality › "Less grain" adds exactly one `temporaldenoise` effect to that clip and one history step. **At 1280 px:** all 7 tiles show without horizontal scroll.
- **Stabilize core:** a pure function test. Feed it 30 synthetic grey frames: a fixed texture shifted by a known jitter (±6 px, seeded). Recovered shifts must be within 1 px. **Mutation:** flip the sign of the inverse → red.
- **Smooth motion:** a 2-frame fixture where a square moves 20 px. The in-between frame's square centre must be 10 ± 2 px away, where a plain blend gives two half squares. **Mutation:** fall back to `frameBlend` → red.

**Pick (the tab's name, ✏️).** **"Clean-up"** (RECOMMENDED), "Polish", "Fix". Tile names: "Crisper", "Less grain", "Auto colour", "Steady", "Smooth motion", "Sharpen for 4K", "Even light". These are ours, not CapCut's.

**Size.** The tab and existing effects are S-M; Stabilize L; Smooth motion M. **Depends on / conflicts with:** S12 (Look goes project-wide), S18 (presets), S19 (Adjust). It shares Stabilize with S33.

### #1243 S29: Beat mapping and automatic beats

**His words (verbatim):** "There also probably should be a way to map beats. And also, like, an auto-generate way to, like, an automatic way to add beats, potentially. Just, like how CapCut does it, like, research what CapCuts add beats features like and what that does and how it works. And we can have something like that as well. Maybe give it a different name than add beats. Because then we'll be like seen as copying."

**How CapCut's works (research).** You select a song, tap **Beats** and turn on **Auto generate**. Yellow dots appear along the waveform. Third-party guides report two densities, "Beat 1" and "Beat 2" (the denser one), but CapCut's own docs don't confirm it. There's also a manual **Add beat** at the playhead. The dots are magnetic: clip edges and the playhead snap to them as you trim and move. AutoCut and templates cut clips to the beat in one step, and "AI movement" in camera tracking adds zooms timed to the beat. The repo's own notes say the same (`tools/design/plans/simple-mode/research/capcut-mobile.md:88`, `:145`, `:292`).

**What's there now.** Mapping is **HAVE (partial)**; automatic is **LOCAL, new**.
- Project marks called "Benchmarks" (`js/app.js:1883-1910`). Tapping the playhead's top while the song plays marks the moment the finger lands (`app.js:8049-8055`, queue 690). The skip buttons step between marks (`app.js:1944-1947`).
- Full snaps to marks (`js/timeline.js:697-719`). Simple snaps to them (`js/simple-timeline.js:394-401`) but never draws them; `:396` is the only reference.
- His pick D19 A: "beat marks stay on the music" (REQUESTS.md:34805; `tools/design/plans/simple-mode/vis/v10.js:383-389`). Project-time marks don't move when the song moves. That's wrong under D19 A.
- Tempo-synced audio effects already take a BPM (`js/audio-fx.js:885-915`). The "Beat Slam" preset lands on the parked playhead (`js/fx-browser.js:231`).

**The change**
1. **`js/pulse.js` (LOCAL, deterministic, chunked like `captions-vad.js`):**
   - Decode to mono at 11 kHz (`FM.decodeAudio(file, { rate })`), then an onset envelope from log-compressed spectral flux (1024/256 STFT).
   - Tempo from the envelope's autocorrelation (70-180 BPM, with a gentle preference for 90-140).
   - Beats placed by dynamic-programming tracking (Ellis 2007).
   - Downbeats taken as the strongest phase in each group of 4.
   - Output `{ bpm, beats[], bars[] }` in the song's local seconds.
2. **Store the marks on the sound layer:** `layer.pulse = { marks, bpm, every: 1 | 2 | 'bar', auto }`, in local time like caption cues, so they move with the song (D19 A). Add a sanitiser beside `js/storage.js:1399-1624` and to the collab schema, or the field drops silently (memory: whitelist drift).
3. **Simple:** the sound item's tray (`simple-tools.js:395`) gets **Pulse**. Its row: Done · Find · Every beat / Every other / Bar starts · Tap to mark (a tap while playing adds a mark at the press time, the 690 rule) · Clear.
   - Dots are drawn on the sound lane. A mark under the playhead lights up.
   - Snapping adds the song's marks to the `snapStart` points (`simple-timeline.js:395-401`) and to Full's (`timeline.js:697-719`).
   - The detected BPM fills tempo-synced audio effects' Tempo when he asks.
4. **Later (phase 2):** "Cut to the pulse" trims the main-row clips so that each cut lands on the next mark (one ripple command).

**Tests**
- **Detector (pure):** a synthetic 120 BPM click track, 30 s, with louder clicks every 4th beat, quieter off-beat hits and noise. BPM must be 120 ± 1. At least 95 % of "Every beat" marks must be within 25 ms of the truth, and they must exclude the off-beats. "Bar starts" must land on the louder clicks. **Mutation:** drop the adaptive threshold → off-beats counted → red.
- **D19 A:** move the song +2 s. Its marks' project times move +2 s. **Mutation:** store project time → red.
- **At 380 px:** Pulse shows in the sound tray, dots draw on the lane, and dragging a clip edge within the snap distance lands exactly on a mark. **At 1280 px:** the same in Full's timeline.

**Pick (the name; avoid CapCut's "Beats", "Auto generate", "Match cut").**
- **"Pulse"**: the button reads Pulse, the dots are "pulse marks", and the action is "Find the pulse". **RECOMMENDED**: one short word that fits a phone tray and is a music word beginners know.
- "Rhythm marks": clear, but long on a button.
- "Hit points": the film-scoring word, punchy but less obvious to a beginner.

**Size.** M for the detector and storage, M for the UI. **Depends on:** S23 (the audio lane under the main row), S35 (keyframes on marks).

### #1243 AI1: Let any AI drive FreeMotion (an MCP server or similar)

**His words (verbatim):** "Also, people should have the ability with this editing software to have their own AI, have like, I can't remember what it's called, but it should be able to have like for the simple editor and the complex one, whatever, AI should have the ability to have a backend, like an MCP, and have the ability to like go in and like use our editing software. So if people want, you know, want their AI, like no matter what AI to use our editing software, they can do that."

**Verdict.** Buildable with no server of ours. A PWA can't *be* an MCP server: it has no process and no port. It can do three things instead:
- register tools with the browser (WebMCP);
- be driven by a small bridge the user runs on a PC;
- hand any chatbot a tool sheet and take its answer back by paste.

**What's there now (the hard part is done)**
- **The single safe door:** `FM.aiOps.applyOps` (`js/ai-ops.js:1-11`, `:131`, `:521`). It accepts only known op names, clamps every number, never runs code and never uses innerHTML. It also refuses to create media (`:7-8`).
- **The vocabulary:** 25 ops (`js/ai-manifest.js:35-46`), including delete, duplicate, select and setTime. Ops look like `{op:'setProp', ref, path, value}` (`ai-ops.js:269-272`).
- **Tool schemas already exist:** they're generated from the live registries (`ai-manifest.js:159-162`, `:209-221`). `FM.aiManifest.tools.ops` (emit_ops) already has the shape an MCP tool needs: name, description and input schema.
- **One sentence, one undo:** the pattern is history mute, then one commit, and the model's text only ever goes out through textContent (`js/ai-chat.js:8-29`).
- **The AI can see the project:** `ai.js` renders a frame to PNG and summarises the layers (`js/ai.js:321-327`).
- **Clip edits:** each of Simple's commands is one undo step (`js/spine-edit.js:1478`, `:2483-2495`, `:3691-3693`). They give us a second, safe vocabulary for what the op list can't do.
- **The key:** the user's Anthropic key (`js/ai-key.js`) must never be reachable from any tool.

**Options**
- **A. WebMCP adapter (S).** `navigator.modelContext.registerTool({ name, description, inputSchema, execute })`.
  - Chrome's early preview (Chrome 146, behind a flag). The API is still moving: provideContext was removed in March. It needs a visible tab, and iPhone Safari doesn't have it.
  - No keys and no network. The user's own browser agent drives the open tab. Detect the feature and do nothing anywhere else.
- **B. Local MCP bridge (L, PC only).**
  - `tools/fm-bridge/` lives outside the app, as one zero-dependency Python file. It speaks MCP over stdio to Claude Desktop, Claude Code or any MCP client, and talks to the open tab by long-poll on `http://127.0.0.1:<port>`. Loopback counts as secure, so the https page may reach it; Chrome asks once for local-network permission.
  - Pairing: a 6-character code shown in the app. The bridge checks the Origin, binds 127.0.0.1 only, and holds a token per session.
  - The phone can't use it.
- **C. Paste bridge (S-M, works on his phone with any AI).**
  - "Copy for any AI" puts the capability digest, a scene summary, the emit_ops schema and a short instruction on the clipboard.
  - He pastes that into ChatGPT, Claude or Gemini, and copies the JSON answer back.
  - "Paste AI changes" parses it (200 KB cap), shows "8 changes: …", and applies it through applyOps as one undo step.
- **D. AI as a live collaborator** (`js/collab-signal.js:1274-1275` relays plus WebRTC). Later; heavy.

**Recommended first step**
1. Build `js/ai-bridge.js`: one tool registry. `describe_project` (read: layers, times, effects; no media bytes). `get_frame` (read; PNG; off unless he allows pictures). `apply_ops` (write, through applyOps). `undo`.
2. Ship adapter **C** (it works today, on his phone, with any AI) and adapter **A** behind feature detection, so it lights up when Chrome ships it.
3. Leave **B** until he has seen A and C working; that's his pick.
4. Phase 2 adds Simple's commands (split, trim, speed, volume, reverse, take sound out) as validated tools.

**Security, built in**
- Off by default: Settings › Labs › "Connect an AI". While it's on, a "AI connected" chip shows.
- Every write goes through applyOps or a Simple command. One call is one undo step. No eval, no innerHTML.
- No tool can read `FM.aiKey`, localStorage or media files.
- Nothing is sent anywhere by us. Only the user's own AI talks to the tab.

**Tests**
- **At 380 px:** the toggle is off on a fresh profile. With a stub `navigator.modelContext`, nothing is registered until the toggle is turned on. **Mutation:** register at load → red.
- **Clamping:** `apply_ops` with `{op:'setProp', ref:<id>, path:'transform.opacity', value:5}` leaves opacity at 1 and adds exactly one history step. **Mutation:** route it to a raw setter → red.
- **The key never leaks:** set a fake `sk-ant-…` key, call every read tool, and JSON.stringify the output. It must contain no `sk-ant-`. **Mutation:** add `FM.aiKey.get()` to describe_project → red.
- **Paste:** invalid JSON changes nothing and shows a message. At 380 px and at 1280 px the paste sheet causes no horizontal scroll.

**Pick (setting name).** **"Connect an AI"** (RECOMMENDED), "Outside AI", "AI hand-off". Transport order: A + C first (RECOMMENDED), B first, or D.

**Size.** M for phase 1 (registry plus A plus C); L for B. **Depends on:** F2 (the assistant's name, folding in AI Scene), S14 (an AI button in Simple's bottom row), G10.
