### #1243 S3: the first row hides when a layer is tapped

**His words:** "where it says clips, text, captions… when you have nothing selected, stays. And then the other layer gets
added on top… a lot to take in… when you actually tap on a layer, that first row goes away."

**What's there now.** Two rows are always on screen in Simple: `#sm-say` (52 px, the tray or the quiet line "4 clips ·
0:15") and `#sm-tools` (56 px, Clips · Text · Captions · Sound · Overlay · Effects). `#sm-tools` never hides, by design D10
A (`js/simple-timeline.js:751-761`, `styles.css:12629`). With a clip selected the tray fills with its tools and the project
row stays under it, so he sees two toolbars. The phone stage height is computed from both rows being there
(`styles.css:12556`, `:12563`: "380 = top bar 52 + play bar 40 + rows 170 + tray 52 + tools 56").

**The change.** Make the bottom area ONE row of constant height whose contents swap (see the combined description at the
end, mode `project` / `item` / `sub` / `panel`).
1. `js/simple-tools.js` `sync()` (`:1258`): compute `mode` and write `bar.dataset.mode`. `item` when one or more items are
   selected and no sub-row or panel is open.
2. `styles.css` (Simple block near `:12589`): `#sm-bar` becomes a 56 px row plus the safe-area inset. `#sm-tools` shows
   only in `[data-mode="project"]`, `#sm-tray` only in `item` and `sub`. Hiding uses `display:none`, but the row's height
   never changes, so nothing above it moves (T19 still holds).
3. The quiet line and the first-run hint leave the row. They become a floating line (the combined description, choice
   A), so the project row is just the tools.
4. Recompute the two stage constants (`:12556`, `:12563`). The 52 px freed goes to the timeline (S23 needs it), so
   `--stage-h` keeps its value.
5. `js/simple-timeline.js` `dockBottom()` (`:754-761`) docks under `#sm-bar`'s row, not under `#sm-tools .sm-tool`.

**Tests** (380 and 1280). With nothing selected, `[data-tool="clips"]` is visible and `#sm-tray` has no client rects.
Select Clip 2: `#sm-tools` has no client rects, the clip's tools are visible, `#sm-bar`'s height is within 0.5 px of
before, and `#stage`'s height is within 0.5 px of before. Deselect: everything is back. **Mutation:** drop the
`[data-mode="item"] #sm-tools{display:none}` rule. The project row then shows under the tray, so the test goes red.

**Pick:** none needed. This clause is the mechanism. The arrangement choices are in the combined description.

**Size:** M. Depends on the combined bar (it IS step 1 of it). It conflicts with D10 A, which his new words supersede.
Existing tests that assert both rows (the `simple P2.2 · tray…` family) must be rewritten in the same release.
