### #1243 F1: empty Media/Audio tabs: buttons go massive

**His words:** "when you have no media or audio added, like all the buttons in those sections are massive. They shouldn't go massive. They should stay small." (complex mode, he says)

**What's there now.** `drawBody()` in js/addmenu.js:1141-1146 moves a Media/Audio tab's own buttons into the small one-row pinned strip only `if (splitTab && opts.some(o => o.mid))`, so this happens only once there are imports. With no imports, every button lands in the page grid. Then js/addmenu.js:1357-1359 adds `addmenu-grid--fill` (and `--cols2` when there is one row). styles.css:1612 stretches those rows to fill the body (`min-height:100%`, rows `minmax(…,1fr)`), and the body is `flex:1` with a 170-260 px floor (styles.css:5232). The result: Media (4 cards: Import media, Sample clip, AI Scene, Assistant, js/addmenu.js:437-470) shows 2 rows of about 170 px each. Audio (3 cards, :490-527) shows two huge columns plus one full-width card. This is queue 428's "fill it", which he has now reversed for these tabs. The PC panel is not affected: `fitOn` there and tileFit caps a stack tile at 118 px (js/tilefit.js:37).

**The change.**
1. In `drawBody`, for `splitTab`, always put the tab's actions (`!o.mid`) in the pinned strip, whether or not there are imports.
2. When the library part is empty, render the ordinary `.addmenu-pager > .addmenu-page`. This keeps the queue-275 invariant that every tab has a body and a pager. The page holds one faint line (`.am-lib-empty`): "Your imports show up here", in textContent.
3. Never add `--fill`/`--cols2` to a page in a Media/Audio tab. F4 applies the same rule to every picture page.
4. Rewrite the test `addsheet-fill` (tests/tests.js:46185) to skip Media and Audio. It currently picks up the pinned grid first via `.addmenu--sheet .addmenu-grid`. Its comment should record that #1243 F1 reverses queue 428 for these two tabs.

**Tests.** At 380, with the library stubbed empty: the Media and Audio action cards are each ≤ 72 px tall. Each card's height equals (±1) the same card's height with one stubbed import. All cards sit in `.addmenu-pinned` on one row. At 1280 (control), the PC panel's card heights are unchanged from HEAD. **Mutation:** put back the `opts.some(o => o.mid)` condition and the test goes red.

**Pick:** the empty line. (A) one short faint line **RECOMMENDED**: an empty box under the strip reads as broken. (B) nothing. (C) a small "Import" arrow drawing.

**Size:** S. Same `drawBody` edit as F4, so ship them together. F2 changes Media's card count. Reverses queue 428 for Media/Audio.
