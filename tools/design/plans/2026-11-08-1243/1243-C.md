# #1243 plans, group C: Simple editor effects, looks, adjust and background (+ FX1)

Planned 8 Nov 2026 by reading the tree at v18.29 (main, clean). This was read-only: nothing was run or measured, so every cause below is **from reading, not measured**. Line numbers match v18.29.

## Shared facts (several plans depend on these)

- **Adjustment layers skip four kinds of ingredient.** An adjustment layer only runs the ADJ_OK grades (js/fx-registry.js:222-249, which says: "Left out on purpose: vignette, gradientoverlay, lightleak, filmgrain…"). If a filter box sits on one, only those grades from its children run (js/compositor.js:29516-29522 `adjKids`, then `applyAdjustment` :29695). The filter's own Grain, Vignette and Sharpen finish sliders are flagged `adjNo` (compositor.js:2549-2557). Several library filters use grain, vignette or a light leak, for example Faded Film, Super 8, Old Film and Bleach Bypass (js/filters.js:73-121).
- **The other whole-picture layer type is a full-frame shape with Backdrop Clone.** compositor.js:2131-2134 says: "A full-screen shape + Copy Background = an adjustment/colour-grade layer you can mask & animate." It's an ordinary layer, so every effect runs on it. It costs "a full-frame blit per layer per frame" (compositor.js:22371-22375).
- **Simple's project row has six tools today:** Clips, Text, Captions, Sound, Overlay, Effects (js/simple-tools.js:312-320). S12 (Look), S21 (Templates) and S22 (Background) each add one, and S14 adds AI. That means S15's scrolling row has to land first.
- **Two layout rules cover every new sheet below.** S9: only one menu is on screen at a time. F10: a sheet stops at the transport row.
- **Every new marker has to be added to the sanitiser.** Effects only keep `sm === 1` (js/storage.js:1928). Layer `sm` keeps the SM_FLAGS (storage.js:2000) plus plain unknown keys. Project `sm` keeps plain unknown keys (storage.js:2057-2073). Each new marker needs its own sanitiser line and a save→reload test, because of the whitelist-drift lesson.
- **His 21 Oct rule:** the RECOMMENDED option ships switched on and he corrects it later. Design clauses are still drawn and shown to him first (#545). G10 is the bar for all of this: run reviewer agents on each one before it ships.

### #1243 S12: Look becomes project-wide colour correction

**His words (#1243 S12):** "the look menu is good… it's just not organized at all… the look menu should be what the effects menu is, and you shouldn't have the look menu on each layer… you want to press add and it goes over your entire project immediately… consistent color correction over your project."
The same idea from his full message: "You want to press add and it goes over your entire project immediately, and you've just got consistent color correction over your project. You don't want any of this like bullshit, like, you know, having to add it to each layer and find it each time."

**What's there now**
- Look is a tool on each clip. `lookT` is defined at js/simple-tools.js:342 and placed in the tray for a video or picture clip at :355. It opens a panel for that one clip: `openLook` :1334, `drawPanel` :1337-1358, the panel itself :747-864.
- The writes are in js/spine-edit.js:2653-2825. Picking a filter puts a Simple-made filter box (sm 1, with an fid) on the clip. Adjust is a second box named "Adjust" (the six controls in LOOK_ADJ :2668-2675). `lookTarget` (:2761) refuses anything that isn't a video or a picture.
- A "Look for all" tool was designed (DESIGN.md §8.5, line 2688) but never built (tools/design/plans/sm3-look/NOTES.md:75-77).
- **This is why it isn't organised, from reading:** the strip is one flat run of tiles. It shows None, his favourites, his own filters, then every library filter section by section, with no headings (`lookList` :766-777, `lookFilters` :815-842).
- The project row's Effects (:319) is a strip of about 45 whole-frame grades (`S.segmentEffects` spine-edit.js:3098, ADJ_OK effects only). That strip already is colour work, which matches what he means by "the look menu should be what the effects menu is".
- On a phone the docked sheet only rises when something is selected (js/mobile.js:57).

**The change**
1. Add **Look** to the project row, before Effects (icon `look`, simple-tools.js:52). This needs S15's scrolling row. The grades-only Effects strip is removed (S13 replaces it). Grade segments that already exist keep their tray.
2. Look edits **one project look layer**. The layer is created on the first pick (pick first, §8.5c) by a new `FM.addLookLayer()`. It's a full-frame layer named "Look", marked `sm.look = true` ('look' is added to SM_FLAGS, storage.js:2000), spanning [first clip start, R.trackEnd]. Its position in the stack follows the pick below.
   - **Step 0 is a probe of about 30 minutes.** Build it both ways on the 1080×1920 sample at the phone quality tier.
   - **R2 is the default:** a full-frame rect shape holding [`copybg`, the filter box, the Adjust box]. Every ingredient renders and the compositor doesn't change.
   - **R1:** an adjustment layer. Full shows it more clearly, but grain, vignette, light leaks and sharpen do nothing on it (see shared facts). R1 is only acceptable together with a compositor change that runs those four on layers marked sm.look, plus `FM.adjNeedsFrame` (compositor.js:29662) returning true for them.
   - Go with R2 unless the probe shows it costs more than 2 ms per frame over R1.
3. Generalise the Look writes:
   - `lookTarget` accepts the look layer.
   - A new `S.planProjectLook(R, op)` handles filter fid, strength, adjust, reset and recipe (S18). Its `plan.pre` creates the layer when there isn't one yet, and the whole thing is one step labelled "Change look".
   - `S.lookOf` and `S.lookApply` (:2681, :2714) already work on any layer's `effects`.
4. Keep the layer the length of the project. Add one `fitLook(R2)` write beside `fitTails` inside `S.edit` (spine-edit.js:1399), running on every step, not only gated ones. It sets start to the first clip's start and duration to trackEnd minus start, and puts the layer back in its slot. Clips added in Full get no silent write on switch. Instead the Look panel says "Look ends before your last clip · Fix", and Fix is one step.
5. Classifier (spine.js:368-386 and :603): sm.look gets its own section, 'look'. That section isn't a key of R.lanes (spine.js:744), so the layer is never drawn as an item. Set `R.look` to its id. S23's effects row can show it later as one thin bar.
6. Remove Look from the clip tray (:342, :355). Clips that already carry a Simple per-clip look keep rendering. The project Look panel shows "2 clips have their own look · Remove them", which is one step and deletes only sm 1 boxes.
7. **Organise the strip:** put a row of chips over it: Favourites, Yours, then the labels from `FM.filters.sections()` (read from the code, never copied, js/filters.js:35-65). Each section starts with a thin divider and its label inside the strip. Tapping a chip scrolls to that section, and the chip for the section in view lights up as he scrolls.
8. **Where the panel opens:**
   - Phone: js/mobile.js:57 gets a branch for when Simple wants its project panel (`FM.simpleTools.projectPanel()`). The docked sheet then rises with nothing selected and replaces the rows (S9).
   - PC: drawn through `drawPanel(root, null)`, the same way Extras is (:1338), with `panelFor = '@look'`.

**Tests**
- 380 px, two clips, nothing selected: Look is in `#sm-tools`. Tapping Noir creates exactly one layer with sm.look, start 0, duration equal to trackEnd, holding Noir as an sm 1 box. The clips' own `effects` are unchanged. A pixel from each clip reads grey, and one undo removes the layer. **Mutation:** make `planProjectLook` write onto the selected clip instead, and the test goes red.
- Append a clip: the look layer's duration equals the new trackEnd. **Mutation:** delete the `fitLook` call and it goes red.
- At 380 and 1280 the clip tray has no `[data-tool="look"]`. The per-clip Look tests at tests/tests.js:197862-198034 need rewriting.
- Every ingredient of every library filter changes the picture on the look layer (reuse queue 858's per-ingredient test on the look layer). **Mutation:** use R1 without the compositor change, and Faded Film's grain goes red.
- Chips: one chip per non-empty section. Tapping "Retro / Analogue" brings that section's first tile into view.

**Pick (✏️):** what the Look covers.
- A: Only the clips (the clip row and Behind).
- **B (RECOMMENDED): clips plus pictures on top.** The look layer sits directly above the top-most video or picture layer, so titles, captions, shapes and stickers keep their own colours.
- C: Everything, titles included.

Second pick, the layout: **chips over one strip (RECOMMENDED, because the picture stays in view on a phone)**, or a tall grid with headings.

**Size:** L. **Depends on:** S15 (scrolling row), S9 (one menu at a time), S19 (what Adjust contains), S18 (Save). **Conflicts with:** S19's Match colour is per clip by nature, so it goes on the clip tray (see S19). S23 decides how the look shows on the timeline.

### #1243 S13: a proper effects library in Simple

**His words (#1243 S13):** "there is literally like not really any effects at all. Like CapCut has like a laundry list… you just basically call it filters… you just gave me a notification saying it's done, but it's definitely not done."

**What's there now**
- **Cause, from reading:** the project row's Effects (simple-tools.js:319) opens a strip in the tray row (`fxFill` :934-958). That strip lists `S.segmentEffects()` (spine-edit.js:3092-3103), which only allows ADJ_OK effects (fx-registry.js:230-249): the colour grades plus Blur, Pixelate and RGB Split. It's grades by construction, so it really is "filters" under another name.
- A pick makes a 3-second segment at the playhead (`S.segmentWhere` :3126-3136), which the app calls "the effect" (spine.js:231). Those complaints belong to S10 and aren't re-planned here.
- The app has about 200 effects (fx-registry.js:10-168) but only 12 shipped presets (js/fx-presets.js:19-42).

**The change**
1. **One shared table for the library**, `js/simple-fx.js`. It's a new plain script, loaded after fx-registry, and S30 uses the same table. Start with about 80-100 entries. Each entry is `{ key, cat, name, type, params, dials, where }`:
   - `name`: Simple's own word.
   - `params`: tuned so the first tap already looks good.
   - `dials`: at most two, mapped to real registry keys, for example Strength → shake `amount` and Speed → `speed` (compositor.js:1765-1769).
   - `where`: 'grade' for ADJ_OK effects, 'copy' for any other whole-picture effect.
2. **Categories are Simple's own** (see the pick below). Hidden from Simple: 3D, Keying, Repetition, Text, and Backfill (which moves to S22).
3. **The sheet:** Effects opens a library sheet, following S9 and F10. It has category chips and a 3-column grid of tiles showing FX1 pictures, with the live render until an effect has its picture. The first tap previews on the canvas (`FM._fxPreview`, the same way Full's browser does). A second tap, or Add, commits it as one step.
4. **Where an effect lands:** over the whole picture for a stretch. The default length is whatever S10 decides.
   - 'grade' entries use today's adjustment segment (`planAddEffect` :3162).
   - 'copy' entries become a full-frame shape holding [`copybg`, effect], marked `sm.fxl` (a new SM flag). Classify it as kind 'effect' by adding `|| sm.fxl` to the check at spine.js:374, so it gets the segment tray (:927-933).
   - On a copy segment, Strength drives its main dial, not opacity. `S.segmentEffect` (:3106) must skip the copybg entry.
5. **Step 0 is a spike (a probe, not shipped).** For each candidate effect, render a copy segment over the sample clip and diff it against the plain frame at three times.
   - Some effects change nothing.
   - Some show the un-moved picture at the edges. Shakes are the likely ones: shake's `zoom` "Zoom punch" or a 1.08 scale covers that.
   - Fix those with the entry's params or drop them. Only effects that pass go into the table, and the probe's list is committed next to the table.
6. **The tray-row strip goes for new segments.** Change effect on a segment opens the same sheet, targeted at that segment.

**Tests**
- **Table sanity:**
  - Every entry's type exists in FM.fxRegistry and isn't hidden. Every param key and dial key exists in that type's schema, with values in range. The test reads these from the registry; it never keeps its own copy.
  - Names are unique. No name equals its type's label in Full, and none matches the BRANDS regex (tests/tests.js:137005).
  - No 'fillbehind', and no threed, matte, repeat or text types.
- 380 px: Effects → Glitch chip → the `glitch` entry, as one step. A copy segment exists with [copybg, glitch], kind 'effect'. The picture inside the stretch differs from the picture outside it. **Mutation:** leave copybg out of the new layer, so the stretch shows the shape's own fill, and the test goes red.
- 1280 px: the sheet sits in the band and shows at least 60 tiles.
- Every table entry passes the spike diff (run the probe as a test, in a slice).

**Pick (✏️):** the category set and names.
- **A (RECOMMENDED): eight plain words of our own:** Move · Glitch · Light · Film · Blur · Bend · Weather · Frame, plus Colour pop for colour flashes.
- B: by mood (Calm, Hype, Retro, Dreamy, Dark). This is risky because CapCut groups its effects by mood.
- C: Full's categories, renamed. That fails his "not a copy" rule.

Show him the sheet drawn at 380 with real tiles.

**Size:** L. **Depends on:** S10 (a segment's length, name and reliability), S9, F10, S15. It shares the table with S30 and gets its pictures from FX1.

### #1243 S18: save your own presets (filters + adjust + quality)

**His words (#1243 S18):** "the ability to have your own like preset filters… filters, then adjust, and then video quality, and then you can save it as a preset."

**What's there now**
- Saved filters already exist, but only from Full. Full's "Save this effect as preset…" stores a container preset (js/fx-presets.js:209 `capture`, :270 `save`, localStorage key 'fm.fx.userpresets', at most 120, :14). `FM.filters.custom()` lists them (filters.js:822-827), and Look's strip already shows them (simple-tools.js:771-772). Simple itself saves nothing.
- A Look is two boxes, a filter and Adjust. One container can't hold both, because a container inside a container is dropped (storage.js:1896). Merging Adjust into the filter would make the filter's Strength fade Adjust too.
- `save()` reports failures with FM.toast (fx-presets.js:276), which Simple bans (spine.js:255).
- Video quality, the third thing he asks for, is S20 and isn't built yet.

**The change**
1. **A look-recipe store for Simple.** It belongs to the device, the same way favourites do (filters.js:772), in localStorage key 'fm.sm.looks', at most 60. Each recipe is `{ id:'l…', name (≤40 chars), fid|null, strength 0-100, adjust:{key:u}, quality:{} (reserved for S20), v:1 }`. Recipes are read through one validator. It gets the allowed adjust keys from `S.LOOK_ADJ` rather than a copy, clamps each value to its control's lo..100, and drops unknown keys.
2. **A Save button in the Look panel header**, enabled once the project look isn't plain:
   - Tapping it shows an inline name field, prefilled "My look N", with `enterKeyHint` done and no `prompt()`, plus Save and Cancel.
   - On success `#sm-say` reads "Saved “Sunday”".
   - On failure, `S.say` gives the reason; never FM.toast.
3. **A "Yours" section comes first in Look's chips (S12):**
   - Each recipe is a tile. `FM.fxThumbs.mountApplied` draws it on the clip under the playhead with the recipe applied, so it shows his own footage, and falls back to the filter's photo tile.
   - One tap applies the whole recipe as **one step** (`S.planProjectLook` with op 'recipe': filter, strength and every adjust value).
   - Long-press or ⋯ on a recipe tile offers Rename and Delete. Delete asks once.
4. If a recipe's filter no longer exists, applying it still applies the Adjust values and says "Its filter is gone · Adjust applied".

**Tests**
- 380 px: set Noir at 60%, Contrast +20 and Warmth −10, then Save as "Sunday". localStorage holds one recipe with exactly those values. In a new project, applying "Sunday" is one undo step: the look layer has Noir at strength 0.6 plus the Adjust values, and undo leaves nothing behind.
- **Validator:** plant a recipe with an unknown key, strength 400 and a 500-character name. It reads back clamped and trimmed. A non-object is dropped. **Mutation:** replace the derived keys with a literal list that's missing 'blacks'. S19's new control is then lost on save, and the test goes red.
- **Failure path:** stub `localStorage.setItem` to throw. `#sm-say` shows the reason and FM.toast is never called.

**Pick:**
- **A (RECOMMENDED): a recipe of values that gets re-applied.** It keeps filter Strength and Adjust separate, survives effect upgrades, and can carry quality later.
- B: bake the look into one filter container. It would show up in Full's Filters tab too, but Strength would then fade Adjust as well.

**Size:** M. **Depends on:** S12 (the project look and the chips), S19 (which controls a recipe holds), S20 (the quality block).

### #1243 S19: Adjust with far more (grain, fade, temperature, blacks, whites, colour match, one-slider, auto)

**His words (#1243 S19):** "its adjust menu… way more options… film grain… fade, temperature, blacks, whites… color match, color correction… one slider… automatically making it look good… auto adjust."

**What's there now**
- Adjust has six sliders (spine-edit.js:2668-2675, words at spine-words.js:208): Brightness, Contrast, Saturation, Exposure, Warmth (`temperature.amount`) and Vignette. Each control has one registry effect, all inside one "Adjust" box. A control set back to 0 removes its effect (:2737-2741).
- The engines for everything he asks for already exist:
  - Highlights & Shadows has `highlights`, `shadows`, `whites` and `blacks`, defaulting to −40, +50, 0 and 0. Its `radius` of 0 means the whole picture (compositor.js:971-990).
  - Colour Temperature has a `tint` param (:245-260).
  - Faded Film (:1654), Film Grain (:795), Sharpen (:299), Clarity & Dehaze (:27201, `clarity` defaults to 30) and Vibrance (:287).
  - **Auto Grade** (:29160): mode Levels, Contrast or Colour, Strength 0-100. It follows the picture frame by frame and starts again at each cut.
  - **Match Grade** (:2508): matches this clip's colour to a reference layer.
- On an adjustment layer, Grain, Vignette and Sharpen do nothing (see shared facts). That only matters if S12 goes with route R1.

**The change**
1. **Let several controls share one effect instance.** LOOK_ADJ gets type groups:
   - `highlightsshadows` holds highlights, shadows, whites and blacks.
   - `temperature` holds temperature and tint.
   - Each type gets an `ident`: the params that make it do nothing. For highlightsshadows that's highlights, shadows, whites, blacks and radius all 0. For temperature it's amount 0 and tint 0. For clarity it's clarity 0. The ident is written when the instance is created, because the registry defaults aren't neutral.
   - An instance is removed only when every control on it is at 0 and none is keyed. `lookValue` and `lookKeyed` read each param separately.
2. **New controls, in one scrolling list with three small headings:**
   - **Light:** Exposure, Brightness, Contrast, Highlights, Shadows, Whites, Blacks.
   - **Colour:** Temperature (renamed from Warmth, because that's his word), Tint, Saturation, Vibrance.
   - **Finish:** Fade (`faded.amount`), Grain (`filmgrain.amount`), Sharpen, Clarity, Vignette.
   - Check at build time that Vibrance's 0 really leaves the picture unchanged. That has to be measured.
3. **One row at the top of the Adjust tab:**
   - **Auto** is a pressed toggle that adds `autograde` with mode Levels at strength 100.
   - Next to it, one slider, **Auto fix 0–100**, sets Auto Grade's strength. That's the "one slider… automatically making it look good".
   - Both write to the project look. Auto Grade measures every frame and starts again at a cut, so it works across the whole project.
4. **Match colour is per clip by nature** (make this clip look like that one). It's a clip-tray tool, **Match**: tap it, then tap the reference clip on the timeline, and `matchgrade` (sm 1, with its layer ref set) goes on the selected clip as one step. Tapping Match again turns it off. This is the one deliberate exception to S12's "not per layer", and he should be told that.
5. Keep the single Reset.

**Tests**
- 380 px: each new control at +50 changes the picture compared with 0. Back at 0, its type has no instance left in the Adjust box. With Shadows at +20 and Whites and Blacks at 0, there's exactly ONE highlightsshadows instance. **Mutation:** drop the `ident` write. Shadows +20 on its own then also applies the default highlights of −40, a highlight pixel darkens, and the test goes red.
- Each slider release is one undo step.
- Auto: switching the toggle on puts `autograde` on the look layer. Setting Auto fix to 40 gives strength 40.
- Match: with two clips, select clip 2, tap Match, then tap clip 1. Clip 2 now has matchgrade (sm 1) with its layer ref pointing at clip 1, and clip 2's mean colour moves towards clip 1's.

**Pick:** the layout.
- **A (RECOMMENDED): one list with three small headings** (Light, Colour, Finish) and sliders like today's.
- B: a row of round dials with one slider under them. That's CapCut's layout, so avoid it.
- C: three tabs. It costs more taps.

**Size:** M, with Match adding about an S. **Depends on:** S12 (route R1 or R2 decides whether Grain, Sharpen and Vignette work across the project). S18 stores these keys.

### #1243 S22: a Background button (image, colour, blur, brand)

**His words (#1243 S22):** "a background option… a specific image, a color, a blur… brand backgrounds… upload your company's like branding… the blur background effect would just be in there instead of like an effect… one of the default settings on the same row as where like audio and text are."

**What's there now**
- **Colour:** the Canvas dialog (⚙) writes `project.background`. It's read at js/app.js:10106-10108 and written at :10243, with the swatches and custom colour input at index.html:1818. The renderer reads it at compositor.js:13190 (`sceneBg`).
- **Blur:** the effect "Backfill" (`fillbehind`, compositor.js:2149-2175) fills whatever a layer doesn't cover with a blurred copy of itself, drawn underneath the whole stack. Its Style can be Blurred copy, Mirrored edges or Solid colour, and it has Blur, Zoom, Dim, Saturation and Vignette controls. It's a per-layer effect in the Blur category (fx-registry.js:78), so Simple's Add effect lists it, because `ITEM_FX_HIDE` at spine-edit.js:3240 only hides 3D, Keying and Repetition. That's why it looks like "an effect" to him.
- **Image:** nothing exists. The classifier only recognises a "background" still in projects that haven't been adopted (spine.js:433-458). After adoption, a picture at the bottom is just an overlay in the Behind lane.
- **Brand:** nothing exists. There's no brand kit anywhere in js/.

**The change**
1. **Background** tool on the project row (needs S15). It opens one sheet (following S9 and F10) with three tabs, Colour, Blur and Image, plus a Brand section:
   - **Colour:** swatches plus a custom colour. One step, `S.cmd.background({kind:'colour', hex})`, writes `project.background` and removes any Simple-made blurs and the background image layer. While Simple is on screen, the ⚙ Canvas block hides its own background row, so the control has one home.
   - **Blur:** Light, Medium, Strong (blur 30, 60, 120) and Off. It writes `project.sm.bg = {kind:'blur', blur}` and ONE `fillbehind` (sm 1, style 0) on every clip-row clip. A `fitProjectLayers` normaliser, next to `fitLook` in `S.edit`, adds it to clips that later Simple steps add and keeps the strength the same everywhere. For clips added in Full, the sheet says "1 clip has no blur · Fix".
   - **Image:** pick a picture and it becomes one layer at the bottom, marked `sm.bg = true` (a new SM flag) and cover-fit. The same normaliser keeps it spanning [first clip, trackEnd]. It's classified 'background' even in adopted projects (spine.js:578 checks sm.bg) and is never a main clip.
   - **Brand:** his brand colours and brand pictures as tiles (step 4).
2. When every clip fills the frame, the sheet shows one line: "Your clips fill the frame, so the background only shows where they don't".
3. Take Backfill out of Simple's effect pickers: add 'fillbehind' to the hidden list at spine-edit.js:3240 and to the exclusions in S13/S30's table. Full keeps it.
4. **Brand kit.** It belongs to the device and stays local. ### #1243 FX1: how approved animated pictures replace the live-rendered thumbnails (planning only)

**His words (#1243 FX1):** "every single effect… Do not copy [Alight Motion]… make a demonstration animation for every single one's picture… a unique image for everything… I want you to do 10. Show them to me… 10 from completely different sections… if I say they look good… I'll tell you to do the rest."

**What's there now**
- Every effect tile is rendered live (js/fx-thumbs.js:1-11).
  - Rendering: a 96-unit sample scene drawn at R = 2, which gives a 192² raster (:16, :38).
  - Movement: two probe frames detect effects that move. Those are cached as a 10-frame strip, which one shared ticker plays every 90 ms, about 11 fps (:16, :1671-1697).
  - Speed: generation is sliced to 8 ms per frame (:1213-1239, :1310).
  - Memory: the cache is about 23 MB after a normal browse and about 72 MB if every effect is opened (:9-11). Layer previews are capped at 10 MB (:1653).
- **The contract every caller uses:** `FM.fxThumbs.mount(canvas, type)`, plus `mountFilter`, `mountPreset`, `mountLayerFx`, `mountApplied`, `remountLive`, `stats` and `stopAll` (:1847-2004). It's called by Full's effects browser, Simple's pickers (simple-tools.js:956, :1041) and Look's tiles (:827).
- fx-art/ holds 18 of his photographs, 10-50 KB each, used as subjects. sw.js caches files as they're used and has no precache list (sw.js:21).
- Memory has caused a crash before: keeping old tiles alive cost 56.6 MB and Safari reloaded the app (fx-thumbs.js:1793-1800).

**The change**
1. **Format: one baked sprite sheet per effect,** `fx-pics/<type>.webp`. Each is a 4×3 grid of 192² cells (768×576), opaque, about 30-60 KB. The logger draws them as canvas code, like the intro takes. A dev page, `tools/design/fx-pics/bake.html`, bakes them with `canvas.toBlob('image/webp', 0.82)` in Chrome, and the WebP files are committed. That keeps the app free of any build step; fx-art's JPEGs are the precedent.
2. **A manifest,** `js/fx-pics.js`, as a plain script with a `?v=` buster: `FM.FX_PICS = { shake: { v: 1, n: 12, fps: 12, cols: 4, poster: 0 }, … }`. It lists approved pictures only. Each image URL also carries `?v=`, so a redrawn picture replaces the copy the service worker cached.
3. **The contract doesn't change for any caller.**
   - `mountKey` (:1820) checks `FM.FX_PICS[type]`, but only for STOCK tiles. Layer previews, presets and filters keep the live render.
   - On the picture path, the tile first paints the live-rendered still straight away, so it's never blank.
   - The sheet then loads with `img.decode()`, and the ticker draws each frame with `drawImage(img, sx, sy, 192, 192, 0, 0, cv.width, cv.height)`, with no per-frame canvases.
   - If the load fails (for example offline before the first fetch), the tile keeps the live render and a warning is logged once.
4. **Frame rate:** 12 fps with 12 frames, a 1-second loop; up to 24 frames are allowed. The ticker becomes time-based (frame = floor(now × fps / 1000) mod n for each entry), so the existing live strips keep their 11 fps.
5. **Memory on an iPhone:**
   - One decoded sheet is 768×576×4 = 1.77 MB.
   - Only tiles on screen animate (IntersectionObserver with a 50% margin).
   - An LRU keeps at most 24 MB of decoded sheets on a phone, about 13, which is roughly one screen of tiles; on a PC the cap is 64 MB. A tile whose sheet was evicted keeps its last frame.
   - With `prefers-reduced-motion`, tiles show only the poster frame.
   - `stats()` gains `picSheets`, `picBytes` and `picCap`.
6. **How the rest get their pictures:**
   - Once he approves the 10, the rest come in batches of about 20 by category.
   - Each batch is drawn and baked, then shown to him as a contact sheet, split up for his phone with tools/phonepages.py. Approved entries go into the manifest.
   - Until an effect has a picture, its live tile stays. A count line in the suite ("pictures: 10 / 196") shows progress without counting as a failure.
   - Every picture is original. Nothing is modelled on Alight Motion's tiles (BEFORE-PUBLISHING.md).

**Tests**
- **Manifest:** every key is a non-hidden registry type, n ≤ 24, and cols × rows ≥ n. Each file loads, and its naturalWidth equals cols × 192.
- **Mount:** plant `FX_PICS.blur` as a 2-cell data-URL sheet (red cell, blue cell). After mounting, the tile reads red, and after one tick it reads blue. **Mutation:** make `mountKey` ignore FX_PICS, so the tile shows the live render, and the test goes red.
- **Memory:** plant 40 sheets and mount 40 tiles at 380. `stats().picBytes` stays at or under the phone cap.
- **Reduced motion:** with `matchMedia` stubbed, the frame never advances.
- **Bad URL:** the tile still shows the live still, not a blank box.

**Pick (✏️):**
- **A (RECOMMENDED): baked WebP sprite sheets, drawn by the shared ticker.** The cost is fixed and they work in every tile.
- B: ship the drawing code and run it live in each tile. It's crisp at any size, but nobody knows what it costs per frame on his phone.
- C: animated WebP in an `<img>`. It breaks the canvas contract, and Safari keeps every frame of every tile decoded.

**Size:** M for the plumbing; drawing about 200 effects is ongoing work. **Depends on:** his OK on the first 10. It provides the library tiles for S13 and S30.
