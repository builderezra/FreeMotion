## #1035 The mic going away mid-take (test gap that needs app code)
**Where (Read):** `voice-rec.js`: the stream is taken at `arm()` (:508-549, `micTracks = s.getTracks()` at :545), a take starts in `start()` (:613), ends in `stop()` (:650) or `finish()` (:672); the only things that end a take are the Stop button, the length cap (`startTick`, :636), going to the background (`bgStop`, :609) and the recorder's own `stop` event. **No listener on the track: nothing listens for `ended` or `mute`** (grep of voice-rec.js: the only `ended` is the audio element's, :356).
**What happens (Measured, fake mic through the suite's `withFakeMic` seam):** a track that ENDS makes Chrome's MediaRecorder stop by itself, so `finish()` runs and the take lands in review, **with no word to the person** (the test's "the panel said nothing"). A track that is MUTED (what an iPhone does for a phone call; I dispatch the `mute` event, as a call would) changes nothing: **3 s later the panel still says Recording and the clock keeps counting on silence** (Measured, red). The second is the real defect; the first is a missing explanation. On iPhone the call case is Guess for the exact event order, the code side is Read.
**Callers traced:** `stop()` is called from the Stop button, the cap, `bgStop` and the `_stop` seam; `finish()` from `onstop`, the 900 ms watchdog in `stop()`, and the too-short path; `releaseMic()` from `finish()`, `close()`, `fail()`. The fix adds one more caller of `stop()`.
**Plan (in the patch):** after the stream is stored, `ended` and `mute` on each track call `micLost()`, which does `stop('The microphone was interrupted, so the take stopped there. Everything up to here is kept.')` when the state is Recording; and `finish()` adds the same note when a track is already `ended` and nobody gave a note (the recorder can beat the event). The existing `ui._note` path shows it in review. Not covered: a mic lost while Idle (before Record), which today leaves a dead meter; left alone, one more line if wanted.
**Test (`P14 #1035`):** for each of `ended` (track stopped, event dispatched) and `mute` (event dispatched): open, wait for the live mic, Record, wait 0.9 s, take the mic away, within 3 s the state must leave Recording, be Review, and show a message. **Red on main** ("…was muted mid-take and 3 s later the panel still says Recording" for mute; "…the panel said nothing" for ended), **green with the patch.**

## #1037 A JPEG with an EXIF rotation tag shows upright everywhere (test gap)
**What the code does (Read):** `loadImageFile` (media.js:801-808) loads the file through an `<img>` and takes `naturalWidth/Height`, so it relies on the browser applying EXIF (Chrome and current Safari do, by default); the compositor draws that element. There is no EXIF code in the app and `exif` appears 0 times in the suite before this test.
**Test (`P14 #1037`, green on main):** a 40 x 20 JPEG with red on the left and blue on the right, EXIF Orientation 6 written by hand (a 36-byte APP1 segment inserted after SOI). It asserts the loaded size is the upright 20 x 40, and that a render through `FM.renderScene` (the export's own renderer) has red on top and blue at the bottom of the drawn picture.
**Mutation-checked (Measured), two:** loader that reports the swapped size: "loads as 40 x 20, not the upright 20 x 40"; loader that decodes with `createImageBitmap(…, {imageOrientation: 'flipY'})`: "the top of the drawn picture is rgb(0,0,254)". (`imageOrientation: 'none'` did NOT change anything in this Chromium, so it is not a usable mutation; I tried it first and it survived.) Restored.
**Not covered:** HEIC, the thumbnail and filmstrip paths (they use `loadImageFile(…, {still: true})`, the same loader), Safari.

## #1038 A custom font travels inside a template or project file (test gap)
**What the code does (Read):** the project file is built by `serializeWith` (storage.js:964-982), which calls `embedFonts` (:988-998): for each library font whose CSS name is used by a text layer and whose file is at most `FONT_EMBED_LIMIT` (4 MB, :3643) it embeds a data URL; the template file does the same (`FM.templates.exportFile`, :3113-3135). On open, `applyEmbedded` (:3742-3760) registers each font whose family this device does not have, stores it and rewrites the font index; the import calls it at :1713. A font over 4 MB is **skipped without a word** (no entry in `omitted`, which names media only; :965, :975): the text falls back on the other device. Collab has its own font transfer (collab-media.js:387-410, :1119-1123), not tested here.
**Test (`P14 #1038`, green on main):** a real 1.7 KB TrueType (DejaVu Sans Mono cut to A a B b H h I i O o, renamed FMP14Test, generated with fontTools) is imported through `FM.fonts.import`; a text layer uses it; the project object from `serializeScene` must carry exactly that font with a `data:` URL; a template saved from the project and exported (download caught) must carry it too; then the font is removed from this device and the project object is imported through `FM.storage.importObject`, after which the font must be back in `FM.fonts.list()`.
**Mutation-checked (Measured), two:** embedding switched off (`if (false && file …)`): "the project file carries 0 font(s) for a text layer that uses one"; registration on import switched off: "opening the file did not register the font it carried". Restored.
**Not covered:** the over-4 MB silent skip (a one-line addition to `omitted` would make it say so), the template IMPORT path (it goes through the same `importObject`), and whether the face renders in the new device's text (the face is registered; I did not draw it).

## #1040 A layer with no transform breaks import, and every launch after a save (MEDIUM; ChatGPT's fix exists)
**Where (Read, entry's lines right):** `sanitizeUnsafeValues` (storage.js:1531) never touches `transform`; `Object.keys(layer.transform)` in scene.js:562 (timeline lane build) throws. **Callers of `sanitizeUnsafeValues`, traced:** the ordinary project open (storage.js:903, every open), `sanitizeImportedLayers` (:1647, from `importObject` :1698, from `history.restore` through `FM.storage._sanitizeLayers` at history.js:71, and from the collab bridge's layer invariant, collab-bridge.js:144), and the collab fingerprint (collab-core.js:145, :220-224, which hashes the sanitised kitchen-sink layers, so a change to this function must not change that hash for valid layers; **Measured: the seven fingerprint tests are 7/7 with ChatGPT's change applied**). The entry's second fix, a `.catch` on the boot `load()` (app.js:6847) so Home still starts, is **not in ChatGPT's commit** (its diff is the storage.js hunk and a test only).
**What I measured on main (the entry said "measured in a headless browser up to load() rejecting"):** importing a layer with the transform missing, null, an array or a string: the missing, null and array cases throw `Cannot read properties of undefined (reading 'opacity')` from the import itself, and **after the first failure the page cannot open ANY project** ("could not open a clean project: …opacity"; a later unrelated suite test, `Squish reacts to a layer moved by an EFFECT`, fails with the same message in the same run: this one defect pollutes the tests that follow, the H41 pattern). The string case does not throw but leaves `transform: "x"` in the layer. An EMPTY object `{}` imports and draws fine on main (green).
**ChatGPT's fix, held against my test (Measured):** `ba154a37`'s `sanitizeUnsafeValues` hunk replaces any non-plain-object `transform` with `FM.makeLayer(type).transform`. With it applied, `P14 #1040` is **green at 1280 and 380** for all five shapes, and nothing else in the slice moved (the sanitiser and import tests are 15/15; on main they are 13/15 for the two reasons above). **I would land it as is, plus**: the boot `.catch` the entry asked for (a bad autosaved project must not stop Home from starting: without it a user who already has such a project in storage stays locked out); and keep the remaining rebuild on a type it does not know (`FM.makeLayer('weird')`) in mind (a layer of an unknown `type` string builds a shape transform, which is fine).
**Test (`P14 #1040`):** each of five shapes imported into its own clean project; the layer must come out with an object transform, `FM.animatedProps` and `refreshAll` must not throw, a render must not throw, and `scale`, `anchorX`, `anchorY` must evaluate to numbers. **Red on main, green with ChatGPT's hunk.** Note for whoever reads the failure on main: only the first shape reports its own error; the rest report "could not open a clean project", which is the symptom, not a separate bug.
