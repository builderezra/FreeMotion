# AU18 app.js: import, the export dialog, init wiring, clip keys, and media layers through duplicate and paste

Branch `hunt/audit-app-5`, against main fba44ca8 (v17.32). Labels: Measured / Read / Guess. Probes in `audit-app-5-scripts/`. Headless Chromium on Linux with autoplay allowed; the video clip is a 12-frame WebM recorded in the page (no H.264 here), the audio a generated WAV, the images generated PNGs.

**Result: no bug found, no code change.** Every probe ran clean. Two probe faults of my own cost time and are listed so nobody repeats them.

## What I ran
1. **Media layers through duplicate, paste, group, replace and undo (Measured, `mediafuzz4.js`).** 60 random operations per seed over image, audio and video layers: add each kind, delete, duplicate one, duplicate a selection, copy and paste a selection, group, ungroup, undo, redo (each followed by `restoreReplacedMedia`) and **the real replace-media sequence** (stash the outgoing file under its revision, `replaceMediaWith`, fit, bump `mediaRev`, commit, save). After every step: no duplicate ids, no dangling parent, **every image and video layer has a media record, and an image's is decoded.** At the end: save, wait, and **every media layer has a stored file under its own id** (IndexedDB), then **a real reopen round trip** (open another project, open this one again): every layer is back, every record exists, **every file's byte size equals what it was**, every image decodes. **7 seeds (1, 2, 3, 4, 5, 6, 7), 60 operations each, 0 failures.** Layer counts reached 29 to 46 per run with 28 to 40 media layers.
   - **A probe fault, so it is not a finding:** my first replace imitation skipped the stash and the save, and the reopen then showed a layer whose file was 1 to 3 bytes different (another generated PNG's size). With the sequence copied from `FM.replaceMedia` (`app.js` 4745 to 4771) it vanishes in all seeds. The failing seeds were 1, 2 and 4; with the real sequence they pass.
2. **Clip keys and shortcuts (Measured, `keys.js`).** 500 random key events per seed (letters, digits, punctuation, arrows, Home, End, Delete, Backspace, Escape, Enter, Tab, Space; random Ctrl, Meta, Shift and Alt) on a scene with shapes, text and a group, with random selections and playhead jumps. After every key: no uncaught error or rejection, no duplicate id or dangling parent, selection and group context alive, **the playhead finite and within the CURRENT project's duration, and the project's size unchanged.** **5 seeds, 2,500 keys, 0 failures.** Then keys typed into a focused `<input>` (s, d, Delete, Backspace, m, brackets, an arrow, Space): the layers, the playhead and the layer count are unchanged. (A first run reported the playhead past the duration at 5.5 s; that was my probe holding an old reference to a project object that history replaces. Read fresh, it passes.)
3. **Importing files (Measured, `drop.js`).** A real `drop` event with a `DataTransfer`: one good PNG (adds 1); a zero-byte PNG; garbage claiming to be PNG; a text file; garbage claiming to be MP4 (each adds 0, says so with one alert, leaves no record-less layer); a PNG with no type and a name like `IMG 0001 (copy).PNG` (adds 1, by extension); a PNG with a 404-character name (adds 1); a mixed drop of good, garbage, text, good (adds the 2 good ones, 2 alerts); 25 copies of one good PNG (adds 25). **No uncaught errors, 0 orphan layers in every case.**
4. **The export dialog (Measured, `exportdlg.js`).** Opened for 30 combinations of project size (16x16, 100x7, 7680x4320, 1080x1920, odd 1081x1921, 3840x2160) and frame rate (30, 23.976, 1000, 0.5, NaN): no throw, no uncaught error, **no "NaN", "undefined", "Infinity" or "null" in any resolution or frame-rate label.** Six hostile remembered-settings strings (null, an unknown format, an object for the quality, not JSON, an empty list, only a version): the dialog opens on a valid format and quality every time.
5. **Init wiring by clicking everything (Measured, `monkey.js`).** A random clicker over every visible button, role=button and tool in the app, dismissing modals between clicks, skipping anything whose label or id suggests export, share, import, camera, delete-project or reload: **about 1,400 clicks, 76 to 103 distinct controls hit per run, at the 800 x 600 desktop layout (seeds 1, 2) and the 380 x 760 phone layout (seeds 1, 2): 0 uncaught errors or rejections, and the scene intact after every click.** ("ResizeObserver loop" messages, which Chromium raises on its own, are filtered.)

## Observation (LOW, not changed)
Importing an unusable file calls `alert('Can’t use “…” — FreeMotion takes video, images and audio.')` (`app.js` 5545) inside the import loop, so a drop with several such files shows several blocking system dialogs one after another, each holding up the files after it. The other failures in the same function go through `FM.reportError`. By the app's own habit (`FM.ask`, toasts) this one is out of place; a single summary toast at the end of the loop would match it. A UX nit, not a defect, so I left it.
