# AU16 fx-registry and fx-thumbs: defaults, ranges, old-param migration, the no-op probe

Branch `hunt/audit-fx`, against main fba44ca8 (v17.32). Labels: Measured / Read / Guess. Scripts and raw JSON in `audit-fx-scripts/`. **Result: no bug found, no code change.** What follows says exactly what was swept, because a clean sweep of 178 effects on one test image at default settings is narrower than it sounds.

**Scope.** All 178 registry effects (`allIncludingHidden`), minus text, filter, the 3D solids, counter, timecode, particles and weather (as in AU12). A 320x240 textured image layer, plate scale 1, at the moments 0.5 and 1.7 s (and others where noted). **Read:** `js/fx-registry.js` normalisation (lines 225 to 270), the `noopAt` and `effectDoesNothing` probe in `js/fx-thumbs.js` (1317 to 1405), `sanitizeEffects` in `js/storage.js` (first 60 lines). **Not read:** the other ~1,400 lines of `fx-thumbs.js` (tile and strip rendering, caches, preset thumbnails), effect presets, and the registry's help text.

## 1. Defaults and ranges are consistent (Measured, `sweep.js` and `sweep2.js`)
For every range parameter: the default is a finite number inside `min..max`, `min < max`, `step > 0`, and a declared `legacy` is also inside the range. For every segment parameter: the default and any `legacy` is one of the option values (options are `[value, label]` pairs; my first pass read them as bare values and listed 100 false problems, which is why `sweep.json` shows them and `sweep2.json` does not). **Zero real problems in 178 effects.**

## 2. An old save renders as the old look, and every difference is declared (Measured, `sweep.js`)
An effect saved before a parameter existed has that key absent. Rendered with `params = {}` against a fresh instance with the defaults, at two moments: 162 of 178 are byte-identical; **16 differ, and for every one of the 16 the differing parameters are exactly ones that declare a `legacy` value different from the new default** (chromakey despill, roundcorners style, filmgrain shape and highlights, edgeglow source and radius, iridescence motion, chromaticaberration radial, linearrepeat spacing, mirrortile shape, electricedges soft, fractalridges mode and speed, shake x6, tiles mode, voronoi motion, stretchseg softness, palettemap mode, halation x3). I looked for a parameter that differs with NO `legacy` declared (the silent case this rule exists to prevent): **none.** Not tested: a renamed or removed parameter, and keyframed values on a legacy key.

## 3. The "changes nothing" probe against reality (Measured, `sweep.js`)
For each effect at defaults on an image layer, `FM.fxThumbs.effectDoesNothing(layer, 0)` against a direct on/off pixel comparison at six moments. **0 wrong verdicts in 178** (neither "does nothing" for an effect that changes pixels, nor "shows" for one that changes none). Five answer `null` (say nothing): four are the queue 794 ghost-gated temporal effects (framestutter, timewarp, temporaldenoise, motionflow) by design, and **pagecurl**, which changes pixels but answers `null` (it could not tell in time); a `null` is the safe answer and I did not find why it is null. The probe was run on a still image, so a temporal effect that needs a video layer was only tested for not lying.

## 4. Out-of-range values (Measured)
The kernels do **not** clamp: 150 of the 178 render a value 50 % past `max` (or below `min`) differently from `max` (or `min`). That would matter only if such a value could reach a kernel. It cannot through the sanitiser: `_sanitizeLayers` clamps on load (blur radius 99999 becomes 50, hue 1e6 becomes 360, wave amount 1e9 becomes 720, chromakey tolerance 7 becomes 1) and drops a non-numeric or out-of-list value. What can still reach a kernel past its range is a keyframe eased with an overshooting curve (an elastic or back ease), which is a looks decision, not a defect (Guess: I did not run an overshooting ease through the kernels).

## 5. Dead zones and parameters with no visible effect (Measured, read for causes)
`sweep2.js` renders 7 evenly spaced values of every range parameter and lists those where the picture stops changing before `max`, does not change below some value, or never changes. It produced ~25 "stops changing early" and ~45 "never changes" lines. **Every one I checked has a reason that is not a bug**, and the pattern is that the test is one parameter at a time at defaults:
- **Documented dependencies:** roundcorners `radius` does nothing while "Continuous curve" is on (its own note says so, `overriddenBy: 'style'`; with the curve off the radius moves 19200 to 18381 pixels and stops at half the shorter side as it should). palettemap `count` above 4 does nothing in "Your colours" (the default), its note says "uses the first 2 to 4"; in "Levels" it does.
- **Pixel ranges authored for a 1080 plate, tested on 320:** border width, drift x and y, orbit radius, tileshift size, dispersion scale, pixelsort length and shake amount stop changing once the effect leaves a 320 px canvas.
- **Integer parameters sampled between integers:** boxblur, lightglow, darkglow, softglow and innerblur passes (3.5 rounds to 4).
- **Needs something this scene does not have:** glow, dropshadow, stroke, longshadow, innerglow and similar act outside the layer's edge, so they read flat on a layer that fills the frame; I re-ran the 37 "flat" effects with the layer at half size, and the ones still flat are secondary parameters of modes that are off by default, matte and map sources, video-only temporal effects (framestutter, timewarp, temporaldenoise, motionflow, objectblur), and time-dependent ones on a single still moment (squish, starfield).
- **Not explained, so listed rather than dismissed:** chromakey `tolerance` stops changing above 0.83 of 1 and mattechoker `contrast` stops changing at 0 of 1 (the sampling is coarse and my chroma test image has little green, so I would not call either a dead zone), blink `duty`, pixelsort `low` and `high`. A proper test needs a purpose-made image per effect; I did not build 178.

## Findings
**None.** Four things I would look at next, none proven: why `pagecurl` answers `null` to the probe; an overshooting ease through the unclamped kernels; renamed-parameter migration (nothing in the registry records a rename); and per-effect probe images for the six unexplained parameters above.

## Not covered
Effect presets and their migration, `fx-thumbs` tile rendering and caches (about 1,400 lines), keyframed parameters on a legacy key, effects inside a Filter container (the nested path), caption-cue effect stacks, and every effect at a non-default setting except the 7-point range sweep.
