- v3.80 — Shapes stay sharp when you zoom in (Ezra's side-by-side: an Alight Motion star with a razor edge vs ours smeared and soft at full zoom). NOT an anti-aliasing problem — the preview canvas was created at PROJECT resolution (canvas.width = P.width) and the zoom was a CSS transform on the wrapper, so the GPU was stretching a 1080px bitmap. Alight Motion re-rasterises the vector at the zoomed size; now so do we. The preview's backing store is sized to the device pixels it actually occupies (CSS width × devicePixelRatio × zoom), and the compositor renders through a matching base transform, so shapes, text and drawings are re-rasterised rather than magnified. THE SAFE PART, because this is the highest-risk file in the app: the scale lives ON the canvas as `__fmRS`, not in a module variable. Comp-space scratch canvases are never stamped, so they resolve to 1 and every existing plate/effect/mask path behaves exactly as before; export and thumbnails render into unstamped canvases and are untouched by construction. All 55 `setTransform(1,0,0,1,0,0)` resets became `baseT(ctx)`, which restores whatever scale that particular canvas carries — one rule, no per-site judgement. Verified by rendering the same scene (star + blurred ellipse + a Vivid Light layer + text) at 1× and at 3×, downsampling the 3× and comparing: on shapes and the manual blend the flat interiors came back mean 0.008, max 4 — geometry is identical, every difference is edge quality. Found and fixed one real bug on the way: drawManualBlendLayer assumed the target was project-sized, so on a supersampled canvas it blended the wrong region — its plate now matches the target's pixel grid (which also makes manual blends sharp). Audio → keyframes could previously only write to five transform props (scale, opacity, rotation, x, y). It can now bake onto any effect control: bass drives Twirl's twist, the kick drives Glitch amount, treble drives blur radius. Measured reach: 169 of the 174 effects have at least one drivable control, 365 controls in total. The Property dropdown rebuilds itself for whichever layer you target, with a group per effect on that layer, and it only offers controls that a continuous envelope can actually drive — a colour swatch or a segmented choice like Mirror's direction is excluded rather than offered and silently ignored. Range and unit come from the same registry schema the inspector's own slider uses, so picking Blur radius gives you px and 0–50, and Twirl Centre X gives you % and 0–100; the default range is "quiet = where the control sits right now, loud = the top of its range", so a bake never yanks the look somewhere unrecognisable on the first try. Values are clamped to the control's own domain, so a hot envelope can't push blur to 200px. Targets are stored as fx:<index>:<key> — the index, not an id, because makeInstance has never stamped ids and position in the effects array is the only stable handle. Verified: baking onto Blur radius wrote 28 keyframes that evaluate to 25.00 → 48.67 → 11.16 → 10.25 across the clip (it genuinely animates), every value landed inside 0–50, the dropdown groups render correctly, the unit and range fields update when you switch control, and both failure modes return 0 without throwing — a stale effect index and a colour param that can't be driven. Checked at 375px: the sheet still fits with the extra grouping, Apply/Cancel reachable.
- v3.92 — Five colour tools stop being single sliders, and Polar Coordinates gets the half of itself that was missing (round 5). POLAR COORDINATES could only ever wrap a rectangle into a circle; the INVERSE — unwrapping a circular image into a straight strip, a clock face into a timeline, a tunnel into a wall — simply had no way to be reached. Both directions now sit under one Direction control. Proved it is the true inverse rather than merely a different-looking map: running rect→polar and then polar→rect on 289 sample points returns every one of them to within 1px of where it started. GAMMA gets per-channel Red/Green/Blue trims that multiply the master, which is how you kill a colour cast — a single master curve can only make a cast lighter or darker, never remove it. COLOR TEMPERATURE gets the other axis of a white balance: Tint (green ↔ magenta), so a fluorescent green cast is finally correctable here, plus Keep brightness, which rescales each pixel back to its original luminance so a warm-up stops also being a brighten. Measured: mean luma 128.28 before, 135.09 after a +80 warm-up, 128.16 with Keep brightness at 100%. VIBRANCE gets the two guards that stop a vibrance pass looking wrong — Protect skin (orange-red hues) and Protect highlights (pixels near clipping, where extra saturation only shifts hue). Measured on swatches at amount 1.8: a skin tone gains 49 points of saturation normally and 5 with the guard at full, while blue sky (51 → 51) and green foliage (48 → 48) are untouched — it is genuinely selective, not a global weakening. GLOW gets Bloom, which stacks the drop-shadow 1–4 times: one pass is a halo, three is something that reads as light. At 1 it emits the exact same filter string it always did, character for character. Verified with the harness: gamma, temperature and vibrance are all 0 differing bytes against the previous commit for both a legacy instance and explicit schema defaults, polar coordinates' displacement field is identical at mode 0 across every sampled point, and every new control moves the render.

- v3.96 — The six shapes are now TRACED from Ezra's references instead of hand-plotted, and ten new shapes join the library. Ezra's verdict on the v3.95 hand-drawn versions was "complete dogshit", and he was right — I was placing points by eye against professionally drawn icons, which is a losing game no matter how many passes I do. So the references get traced properly: threshold the bitmap, find connected components, follow the boundary by chaining unit edges (a Moore-neighbour walk kept terminating on its own seed), average around the closed loop to kill the pixel staircase, simplify with Ramer-Douglas-Peucker, then flag each vertex smooth ONLY where the path genuinely turns gently — so the check keeps its sharp point and the key keeps its teeth while every curve stays a curve. Three things that mattered: taking only the largest ink blob silently dropped the thumbs-up CUFF and reduced the envelope to its flap triangle, because both references are several separate blobs — so the tracer takes the N largest and normalises across all of them together. Holes are found as background regions that don't touch the border, which gets the key's ring and the car's windows for free, and they're wound opposite to the outline (all traced loops come out the same way round, so they must be flipped or they fill in solid). And normalising had to STRETCH to fill the box rather than letterbox, with the reference's true aspect handed to SHAPE_ASPECT instead — letterboxing there and then applying the aspect multiplier pads the shape twice and renders it small inside its own box. TEN NEW SHAPES: Squircle (a real superellipse — the Apple corner, where curvature stays continuous instead of snapping from a straight edge into an arc), Cross, Map pin, Lock, Gear, Crown, Eye, Music note, Starburst and Clock. The cross is a plus rotated 45° rather than an X plotted from corners, because corner-plotted arms come out uneven the moment the box isn't square. IMPORTANT, and written into BEFORE-PUBLISHING.md: the six traced shapes are derivatives of specific stock drawings (two of the references still carried Dreamstime and Shutterstock watermarks). The forms themselves aren't protectable and the risk is narrow, but they need redrawing from scratch before anything ships publicly. The reference images were deliberately not committed.

- v3.98 — Tiles closes the gap properly, in both modes (Ezra: "the tiles effect still doesn't close the gap fully and work as it should, work extra hard on that"). There were THREE separate causes, which is why it kept almost working. (1) THE BIG ONE: Extend mode spaces its copies by the layer's measured bounding box, but it was being handed the FAST bounding box — a scan of a 4× downsample, which the code's own comment elsewhere describes as having "~12px slack". Any slack in that rectangle is transparent margin baked into every copy, so it becomes a gutter between them, and no gap setting can remove it because the gap slider isn't what's creating it. Tiles now gets an exact, per-pixel bounding box (like Rounded Corners already did, and for the same reason), and the fixed ±2px inset that was trying to compensate for the slack is gone — it couldn't work, since the error varies with the content. (2) Grid mode divided the frame as W/n, which is fractional for most sizes: 1920÷7 isn't a whole number, so every cell landed on a fractional pixel, canvas resampled the edge column, and the soft result read as a seam. Cell edges now snap to whole pixels and are derived from rounded boundaries, so cell k ends exactly where cell k+1 begins. (3) Even with all that exact, a hairline remained, and the arithmetic explains it: the content's own antialiased boundary column is about 50% alpha, and two of those butted together composite to 75%, not solid. So at gap 0 copies now overlap by TWO pixels — one is not enough (measured: one pixel of overlap gave alpha 192, two gives 255), which puts a fully opaque column under the soft one. Verified by counting seam pixels (interior pixels that aren't fully opaque while both neighbours have coverage): Extend at gap 0 is now 0 seams horizontally and vertically, 0 with mirror on, 0 with an ellipse instead of a rectangle, and Grid is 0 at counts 3, 5 and 7 on a 400×300 frame that divides evenly by none of them. The gap slider still opens real gaps when you actually want them, which was the other half of "work as it should". Note this DOES change existing projects that use Tiles — that is the point, they were rendering the gutter.

- v4.00 — RGB Split can finally tear in a direction, and Pixelate's blocks stop being square (round 8). - v4.67 — **fixing v4.66's own regressions**, found by an adversarial review of the commit rather than by use. - v4.70 — **the reverse-playback frame cache stops being able to OOM-kill a phone.** The cache decodes a clip into ImageBitmaps so reverse and slow-mo scrub smoothly, capped at a flat `maxBytes: 384MB` on every device — with a comment saying the cap existed so a long reversed clip "can't OOM-kill mobile Safari".
