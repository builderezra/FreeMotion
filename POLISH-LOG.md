- v3.80 — Shapes stay sharp when you zoom in (Ezra's side-by-side: an Alight Motion star with a razor edge vs ours smeared and soft at full zoom). NOT an anti-aliasing problem — the preview canvas was created at PROJECT resolution (canvas.width = P.width) and the zoom was a CSS transform on the wrapper, so the GPU was stretching a 1080px bitmap. Alight Motion re-rasterises the vector at the zoomed size; now so do we. The preview's backing store is sized to the device pixels it actually occupies (CSS width × devicePixelRatio × zoom), and the compositor renders through a matching base transform, so shapes, text and drawings are re-rasterised rather than magnified. THE SAFE PART, because this is the highest-risk file in the app: the scale lives ON the canvas as `__fmRS`, not in a module variable. Comp-space scratch canvases are never stamped, so they resolve to 1 and every existing plate/effect/mask path behaves exactly as before; export and thumbnails render into unstamped canvases and are untouched by construction. All 55 `setTransform(1,0,0,1,0,0)` resets became `baseT(ctx)`, which restores whatever scale that particular canvas carries — one rule, no per-site judgement. Verified by rendering the same scene (star + blurred ellipse + a Vivid Light layer + text) at 1× and at 3×, downsampling the 3× and comparing: on shapes and the manual blend the flat interiors came back mean 0.008, max 4 — geometry is identical, every difference is edge quality. Found and fixed one real bug on the way: drawManualBlendLayer assumed the target was project-sized, so on a supersampled canvas it blended the wrong region — its plate now matches the target's pixel grid (which also makes manual blends sharp). - v3.91 — Audio can now drive EFFECT parameters, not just move/scale/fade. This was flagged in EFFECTS-PLAN.md as the single highest-leverage change in the whole plan — worth more than any individual effect — because it doesn't add one feature, it makes the catalogue you already have beat-reactive. Audio → keyframes could previously only write to five transform props (scale, opacity, rotation, x, y). It can now bake onto any effect control: bass drives Twirl's twist, the kick drives Glitch amount, treble drives blur radius. Measured reach: 169 of the 174 effects have at least one drivable control, 365 controls in total. The Property dropdown rebuilds itself for whichever layer you target, with a group per effect on that layer, and it only offers controls that a continuous envelope can actually drive — a colour swatch or a segmented choice like Mirror's direction is excluded rather than offered and silently ignored. Range and unit come from the same registry schema the inspector's own slider uses, so picking Blur radius gives you px and 0–50, and Twirl Centre X gives you % and 0–100; the default range is "quiet = where the control sits right now, loud = the top of its range", so a bake never yanks the look somewhere unrecognisable on the first try. Values are clamped to the control's own domain, so a hot envelope can't push blur to 200px. Targets are stored as fx:<index>:<key> — the index, not an id, because makeInstance has never stamped ids and position in the effects array is the only stable handle. Verified: baking onto Blur radius wrote 28 keyframes that evaluate to 25.00 → 48.67 → 11.16 → 10.25 across the clip (it genuinely animates), every value landed inside 0–50, the dropdown groups render correctly, the unit and range fields update when you switch control, and both failure modes return 0 without throwing — a stale effect index and a colour param that can't be driven. Checked at 375px: the sheet still fits with the extra grouping, Apply/Cancel reachable.
- v3.92 — Five colour tools stop being single sliders, and Polar Coordinates gets the half of itself that was missing (round 5). POLAR COORDINATES could only ever wrap a rectangle into a circle; the INVERSE — unwrapping a circular image into a straight strip, a clock face into a timeline, a tunnel into a wall — simply had no way to be reached. Both directions now sit under one Direction control. Proved it is the true inverse rather than merely a different-looking map: running rect→polar and then polar→rect on 289 sample points returns every one of them to within 1px of where it started. GAMMA gets per-channel Red/Green/Blue trims that multiply the master, which is how you kill a colour cast — a single master curve can only make a cast lighter or darker, never remove it. COLOR TEMPERATURE gets the other axis of a white balance: Tint (green ↔ magenta), so a fluorescent green cast is finally correctable here, plus Keep brightness, which rescales each pixel back to its original luminance so a warm-up stops also being a brighten. Measured: mean luma 128.28 before, 135.09 after a +80 warm-up, 128.16 with Keep brightness at 100%. VIBRANCE gets the two guards that stop a vibrance pass looking wrong — Protect skin (orange-red hues) and Protect highlights (pixels near clipping, where extra saturation only shifts hue). Measured on swatches at amount 1.8: a skin tone gains 49 points of saturation normally and 5 with the guard at full, while blue sky (51 → 51) and green foliage (48 → 48) are untouched — it is genuinely selective, not a global weakening. GLOW gets Bloom, which stacks the drop-shadow 1–4 times: one pass is a halo, three is something that reads as light. At 1 it emits the exact same filter string it always did, character for character. Verified with the harness: gamma, temperature and vibrance are all 0 differing bytes against the previous commit for both a legacy instance and explicit schema defaults, polar coordinates' displacement field is identical at mode 0 across every sampled point, and every new control moves the render.
- v3.93 — Spectral Map gets the third of its spectrum that was unreachable, plus depth on Exposure, Colorize and Duotone (round 6). SPECTRAL MAP had a real bug hiding behind its hardcoded numbers: the HSV wedge chain stopped at 300°, with everything above folded into the 240–300 formula. Because the sweep was welded to 260°, that branch could never be reached — so the bug was invisible until the span became adjustable. It now has the missing 300–360 branch, and Spectrum span, Hue offset and Saturation. Proved the new branch is real, not just present: a near-black input at span 360 now maps to 68,0,10 — red-dominant, which is what that wedge should be — where the old final else would have produced a blue-dominant magenta. EXPOSURE was a bare multiply that hard-clips, so pushing a stop up smashed highlights into flat white and there was no way to touch the black point at all (multiplying never moves black). It gains Black point and Highlight rolloff, the latter a soft shoulder that is asymptotic to 255 rather than clipping. COLORIZE had its shadow floor hardcoded at 0.25, fixing the contrast of every wash, and could only replace the image — never sit over it. It gains Shadow lift and a Blend mode (Tone / Multiply / Screen / Overlay). DUOTONE's luma→colour ramp was a straight line, so the handover between shadow and highlight colour was fixed and every duotone landed in the same place; it gains Balance to move that handover and Contrast to widen or flatten the ramp. Duotone was also the second effect this week found holding two copies of the same loop (per-layer and adjustment-layer), which is exactly how the two drift apart — both now call one shared kernel, same as threshold in v3.90. Verified: exposure, colorize and spectral map are 0 differing bytes against the previous commit for legacy instances and explicit defaults; duotone was checked against an independently hand-computed reference of the original ramp (133.9, 85.0, 87.4 vs a rendered 134, 85, 87) and both its code paths return identical pixels at defaults AND with balance engaged. One thing worth recording because it nearly shipped: rewriting these catalogue entries by hand, I typed exposure's default as 0.5 when it has always been 0.8, and dropped its ' EV' unit and colorize's colour label. Diffing my rewrite against the previous commit's entries caught all three — a new instance would otherwise have quietly come out at the wrong exposure.
