# #47 Worker-backed MP4 export, forward port

Starting commit: `c356e30c2632cdb0d88c20fdfd8d4add3a6d1ad6` (consolidated local branch). Original unmerged milestone: `470715a364dee395ef43b4a019d56eaf9553e248` (`codex/worker47-integration`). Local branch: `chatgpt/47-worker-forward`. Nothing was pushed or deployed.

The MP4 export path can render eligible scenes in a Worker using the shared compositor. It captures the scene, media and fonts before asynchronous setup, preserves that snapshot for main-renderer startup fallback, and includes renderer/assets in the resume identity so incompatible saved chunks are not spliced together. Existing main-thread rendering remains the fallback when eligibility or Worker startup fails.

Forward-port changes: `index.html`, `js/render-canvas.js`, `js/scene.js`, `js/eases.js`, `js/compositor.js`, `js/fx-registry.js`, `js/export-worker.js`, `js/exporter.js`, `js/export-resume.js`, `js/storage.js`, `js/studio-fonts.js`. Added/updated focused Worker fixtures and `tests/tests.js` under `tests/`; all changed script cache tags were advanced in `index.html`. The new `{ item: 'TBD' }` test checks a normal Home project carrying metadata and compares regular/bold bundled Inter pixels on the page and in the Worker at two times. A preexisting geometry fixture now verifies that shapes added since the original milestone stay on the existing renderer until their parity is tested.

Checks: targeted browser regressions passed: MP4 frames/fallback/cancel/resume, effects, full admitted-shape geometry, moving video, imported/system text, captured audio, asynchronous snapshot/fallback, and the new Home/Inter parity test (8 tests, all green; geometry fixture covers 1,108 cases). A first test-run app load missed several scripts; the immediate fresh-profile rerun passed. JavaScript syntax checks passed for the modified scripts, and Git diff checks passed. Node-only CJS unit scripts were not run because Node is not installed on this host.

Limits: this is a guarded MP4 milestone, not complete migration of every export mode. Unsupported effects/features, newly added shape kinds, reversed/frame-blended or speed-changed video, and clips using Loudness Match stay on the established main renderer. GIF and still/frame export paths remain on the main thread. Physical iPhone performance and long-project memory use are UNVERIFIED here.
